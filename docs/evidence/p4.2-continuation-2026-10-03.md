Earlier failed attempts are retained only in ignored run directories and are
not admitted as goldens. Investigation corrected real fixture/tool behavior:

- ComboBox wrapper nodes may lack SelectionItem; lookup now requires the
  requested provider pattern as well as the stable ID.
- Owned dialogs may live under the fixture owner in the UIA tree; lookup covers
  the owned subtree and only matching direct desktop children.
- Detached WPF buttons can remain callable (`retained_callable`), and destroyed
  windows can retain readable metadata (`retained_metadata`). The capture
  records these outcomes, demonstrates the synthetic stale-call mutation,
  restores the case, and verifies current tree/native-window identity changes.
  A future adapter must invalidate old bindings before mutation, not assume a
  provider exception. No adapter guard is claimed here.
- Asynchronous reset requires an acknowledgement sequence; revision zero is
  not sufficient. Atomic readers use delete-sharing, and writers retry only
  transient sharing/lock violations with a two-second deadline.
- Default WPF off-screen behavior follows visibility, not clipping. The fixture
  explicitly uses the documented
  [FromClip behavior](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.isoffscreenbehavior?view=windowsdesktop-10.0)
  for the clipped button; the earlier mismatching capture was rejected.
