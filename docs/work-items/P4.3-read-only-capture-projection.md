# P4.3 S2 — bounded read-only capture and projection

Status: revised proposed design on 2026-10-04; not implementation entry or
runtime acceptance. Initial independent review identified ambiguity in selected
value references, stable identities, modal discovery and shared safety/budgets;
this revision requires actual re-review, not automatic approval.
Only a separately dated delegated decision after actual independent review
can freeze this design and authorize implementation.

Predecessors: [accepted ADR 0017](../adr/0017-windows-uia-adapter-trust-boundary.md),
[bounded slices](P4.3-implementation-slices.md), accepted P4.2 canonical evidence,
and a separate limited S1 decision. The successful S1 pair alone is not entry.
Owner: coordinating agent `/root`, under the
[maintainer's explicit delegation](../reviews/phase4-agent-review-authorization-2026-10-03.md).
Rust remains preferred; this isolated managed comparison does not select a
production language or start P4.4/P4.5.

## Outcome and boundaries

An owned synthetic Windows application produces a bounded core 0.1 snapshot
whose names, control states and reviewed semantic descriptors are observed
through real UIA. Human presentation is unchanged. No screenshot, arbitrary
application, native selector or fixture-state shortcut enters the projection.

Keep implementation under `experiments/windows-uia/managed-reference/`, with
a separate capture worker/launcher and comparison verifier as needed. Do not
modify the accepted P4.2 fixture, capture tool, goldens, canonical review,
public `src/`, protocol schemas/corpora, dependency lock or npm exports. Reuse
the pinned cached SDK without installation/elevation. Keep S1's executable
suite intact and distinguish any new aggregate binding from its accepted one.

The capture adapter has no mutating pattern methods, retained caller peers,
action executor, external endpoint, persistent host or input fallback. A
separate fixed trusted setup driver may invoke only this fixture's reviewed
synthetic controls to recreate golden scenarios; it is not caller-authorized
execution and cannot satisfy S3 action/policy/postcondition criteria.

## Data and admission

1. A fixed launcher admits only its newly created fixture and worker, retains
   their owned process objects, validates exact binaries/source pins and output
   directories, and preserves failures. No PID/HWND/path/selector from a model
   or arbitrary caller is accepted. No other-process enumeration is added.
2. Reuse or conservatively extend the reviewed OS user/session/desktop/integrity
   and process/window-liveness boundary. The fixed single-dispatcher fixture
   permits `EnumThreadWindows` only for the native owning thread of the already
   admitted main HWND, after owned PID and ordinary desktop checks. No
   Process.Threads, EnumWindows, desktop UIA traversal or caller thread/window
   input. Stop at 64 nonchild callback candidates per enumeration; abort on
   overflow/fault/unprovable ownership before provider text. Require at most
   one additional live visible/enabled direct-owner-main subject, on that same
   admitted thread/process/desktop, for an expected modal or expanded popup.
   Multiple qualifying subjects or a missing expected subject fail closed;
   never pick a first ID/name match. GW_ENABLEDPOPUP is not uniqueness proof.
   Before publication repeat the bounded enumeration and compare the exact
   candidate set/identity, direct GW_OWNER, thread/PID/desktop and process/root
   lifetime. A different-thread popup requires retained failure and separately
   reviewed refinement, not broader enumeration. A UIA ID/ancestry alone never
   admits a top-level window. Record this admission delta for source review.
3. Walk the current admitted Control View with depth, node, child, cycle and
   time limits. Check current process ownership and parent membership. Only
   private salted runtime-instance observations and opaque host references
   are retained; none become a public native selector.
4. Read explicit safety properties using `ignoreDefaultValue: true`, before
   Name, value, selection-content or pattern state. Preserve S1's distinction
   between exact NotSupported, malformed/null values and known Boolean values.
   Unknown structural safety does not invent a safe/default false value.
5. Recheck admission, root lifetime, private membership and reset fence after
   capture. A change or failure discards the candidate and invalidates its
   host-owned generation/revision; no partially collected snapshot is success.
   Sequential UIA reads and fences are not an atomic hostile-provider snapshot.

## Redaction and semantic mapping

Use a copied, bounded internal observation DTO and a separately testable pure
projector. Never serialize AutomationElement, pattern wrappers, exceptions,
native handles or arbitrary provider objects. Correlation is private; fixture
IDs and manifest labels are comparison hints, not authority or observed state.

- Known nonsensitive nodes may supply bounded Name and supported semantic
  state after explicit basic-safety observations. Do not read HelpText,
  descriptions, TextPattern content or unneeded provider fields in S2.
- Sensitive or unknown-password nodes have no Name/value/content/pattern reads
  and no action descriptors. For the known sensitive fixture subject use only
  its reviewed fixed nonsensitive host label and `state.sensitive: true`.
  Unrecognized/unknown-sensitive structural wrappers are omitted from the
  public flat semantic list, retaining only private membership. Do not claim
  `valuePresent` without a separate safe observation; omission means unknown.
- Unknown enabled/offscreen or unknown per-pattern semantic state cannot
  silently become enabled/visible/unchecked/unselected/collapsed/writable.
  Any unknown password, enabled or offscreen basic flag keeps the node solely
  as private structural membership: no Name/value/selection/content/pattern
  reads and no public semantic node or descriptors. Known disabled/offscreen
  values are distinct from unknown and follow the reviewed read-only/exclusion
  policy, not invented unknown defaults.
  Omit an unknown optional semantic field or fail the required golden case
  closed. Such a target has no actionable descriptor. Wrong types, invalid
  enum values, nonfinite ranges or resource violations refuse the capture.
- Reviewed roles/types are Window/window, Button/button, Edit/textbox,
  CheckBox/checkbox, List/listbox, ListItem/option, ComboBox/combobox,
  RadioButton/radio, Tab/tablist, TabItem/tab, Group/button for the reviewed
  expandable subject, Slider/slider, Text/text or the reviewed status role,
  and Custom/generic. Arbitrary type/ID/text cannot confer a special role.
  Freeze trusted subject definitions from the reviewed manifest mapping,
  qualified by private correlation, reviewed type, required pattern families
  and current container. Remaining or unknown-safety same-type/container
  ambiguity refuses the capture. A Combo Text wrapper or unreviewed chrome
  remains private structure, not a second published subject. Each qualified
  semantic subject has exactly one inverse correlation entry. Never use the
  golden/oracle's expected node list as a runtime filter to force parity.
- Value state comes from explicitly supported nonsensitive Value property,
  bounded to 64 characters. Known read-only controls may be read, never gain
  a write descriptor. No password value is requested, even to redact later.
- Toggle state maps On/Off to checked true/false; Indeterminate is not false.
  ExpandCollapse maps Expanded/Collapsed only; other states do not invent a
  Boolean. SelectionItem supplies an explicit Boolean selected observation.
- Selection/ComboBox/Tab values come from a bounded current selected-item
  relationship, never fixture `after.selection/combo/tab`. GetSelection's
  default empty array is not proof of a supported known selection. Require
  typed explicit SelectionProperty support with `ignoreDefaultValue: true`,
  current Selection pattern shape and at most one selected item. Each selected
  peer, including one outside the main copied tree, must pass explicit safety
  classification before Name/content/pattern reads, owned-process checks,
  typed SelectionItem support, explicit IsSelected true, explicit current
  SelectionContainer equal to the expected admitted container and bounded
  current parent/ancestor proof to the admitted main or separately OS-admitted
  popup root. Recheck the item/container/root relationship before publication;
  an ID or matching label is not proof. Unknown safety never reads its text or
  pattern state. Reject ambiguous/replaced/outside-container/unsupported or
  unprovable relationships. No unbounded search or collector expansion.
  Public `state.value` is a stable opaque selected-item element reference,
  never AutomationId, fixture selector, raw runtime ID or a provider handle.
  It equals that item's public node ID when the item is visible. An item absent
  from the visible flat list can have a private proven current relation and
  opaque reference, counted against the same 256 binding cap; the snapshot
  makes no claim that this item is visible or executable.
- RangeValue yields finite value/min/max and explicit read-only state. Validate
  ordering/bounds before invariant numeric-string projection and reviewed
  schema descriptors; do not hardcode observed value or limits from the oracle.
- Hidden/offscreen/empty-rectangle nodes are excluded from the visible semantic
  list like the accepted golden mapping, but remain bounded private structural
  observations. Bounds are omitted rather than publishing native geometry.
- Injection labels remain plain untrusted JSON text, with no HTML evaluation,
  interpolation into commands or instructions, policy or error-message use.

Selection observations may require an additional bounded read-only relation
walk on the real provider. If collapsed/expanded popup relationships cannot
be proved within these rules, retain the failing evidence and seek an actual
reviewed design refinement; do not relax membership to force conformance.

## Opaque projection and read-only capability

Mint independent random opaque surface and element references; bind elements
privately to the current host generation and observed instance/container.
Within a generation reuse the exact surface reference and per-instance/container
element map across unchanged captures, including proven selected-item relations.
Do not mint fresh IDs on every capture and then pretend revision is unchanged.
Removed/replaced/container-swapped relations retire their references; subsequent
rediscovery cannot resurrect one. Reset/window/process replacement rotates the
surface generation and element map. Bound all visible and auxiliary entries
together, not separate unbounded maps. Exhaustion invalidates, not recycles.
Mint locally monotonic semantic revision strings from canonical copied
semantic state and identity generation, not fixture revision/generation,
golden IDs/timestamps or provider counters. Identical captures keep the semantic
revision; changed semantic data advances it; reset/replacement/restart rotates
generation and invalidates old references even when fixture state resets.
Overflow/failure/disposal invalidate rather than reuse old authority.
Freeze the semantic fingerprint over the copied published subjects, reviewed
roles/names/states/descriptor metadata, current private instance/container
relations and host generation. Exclude generatedAt, fixture/oracle counters,
provider events, case IDs and report/measurement timestamps. Stable opaque
references do not themselves create new semantic observations. Unit tests must
prove time-only captures do not churn revision, and state/container/generation
changes do, independently of static expected golden fields.

Only core 0.1 fields may be serialized. Use a fixed nonsensitive native URL,
bounded observed title and generated UTC timestamp. Omit optional
focusedElementId in S2 and do not read focus; omission is not a claim of no
focused control. No focus normalization or invented focus evidence is allowed.
The actual snapshot capability is `snapshots`, not `actions`, `events`,
`deltas`, cancellation or a claim of a negotiated external service.

Action entries in the internal golden-comparison representation are descriptive
pattern/schema metadata, not executable callbacks or an action capability.
For any model-facing S2 read-only snapshot, emit `actions: []`. Keep the two
representations explicitly distinct, validate both with the unchanged core
schema, and never describe the read-only snapshot as exact action-catalog parity.
The comparison verifier may compare reviewed descriptor metadata against the
goldens to prepare S3; S3 must separately supply executable evidence before
an actual action catalog is advertised. No action requests are exposed in S2.

## Frozen proposed budgets

| Resource | Proposed hard checked limit |
|---|---|
| combined current-tree plus auxiliary unique nodes / depth / children | 256 / 16 / 64 |
| admitted main plus modal or popup graph roots per capture | 2 |
| native candidates per owned UI-thread enumeration / enumeration passes | 64 / 2 |
| per Name/correlation string / nonsensitive value | 256 / 64 characters |
| aggregate copied text per capture | 131,072 characters |
| supported pattern families / descriptors per node / all descriptors | 7 / 1 / 64 |
| selected items per reviewed single-selection container | 1 |
| extra selected-item relation walk | depth 16; at most 64 auxiliary nodes, included within combined 256 |
| copied public nodes / opaque element bindings | 256 / 256 |
| one encoded snapshot / one complete evidence report | 262,144 / 1,048,576 bytes |
| snapshot encoding / report parsing depth | 16 / 16 |
| one observation/startup / unit worker / native worker | 10 / 30 / 240 seconds |

One shared stopwatch and text/node/binding counters cover main/modal/popup
trees, selected-item relations, both native enumeration passes, safety reads
and pre/post admission fences; no auxiliary operation gets a fresh ten seconds
or resets the aggregate budget. Repeated private relation verification remains
depth-bounded; duplicate instances cannot count as different public references.
Apply checks before DTO/list growth or provider-shaped enumeration; use a
counting/capped UTF-8 output stream to refuse over-budget serialization before
publication. No truncation may change identifiers, state or eligibility.
This bounds managed copied data/serialization, not provider/COM allocation
inside one getter or hard per-getter latency. The unchanged owned-worker kill
deadline contains a blocked call; report that distinction. Report files are
CreateNew in the admitted owned run directory, not rewritten failed attempts.
The stricter snapshot cap is below the existing 1,048,576-byte protocol cap;
it does not change public protocol limits or widen S1's bindings limit.

## Evidence, tests and acceptance

Freeze exact source, binaries, setup case IDs/order, budgets and verifier before
real execution. Unit/fault injection is not actual native/OS evidence. Required
actual separate reviews cover accessibility/interoperability, security and
package/protocol evidence; root cannot write their dispositions.

1. Pure projection tests cover malformed/unknown state, enum/range cases,
   copied immutable data, ambiguity, sensitive getter-not-called assertions,
   private-ID leakage, inert injection text, limits/cycles and capped encoding.
   Cover duplicate selection labels, collapsed private selected peers,
   replacement/stale opaque selection references, inverse-map collisions,
   arbitrary value strings not rewritten, unknown-basic getter-not-called,
   structural wrappers not published and competing/missing modal subjects.
2. Live revision/generation tests prove changed values alter semantic revision,
   unchanged captures stay stable and reset/replacement/restart do not recycle
   authority. Do not claim unseen identical-tree ABA or mutating atomicity.
3. Recreate all 22 accepted P4.2 golden scenarios, including separately
   admitted modal snapshots. Setup operations and provider rejection probes
   remain explicitly trusted synthetic setup, not adapter actions. Do not
   repeat P4.2's retained stale-peer mutation probe as adapter authority.
4. Compare complete required semantic nodes, names, states and descriptive
   schemas/actions through a private bijective inverse correlation table.
   Exact allowed translation is surfaceId/element IDs, host-owned revision and
   generatedAt, fixed native URL versus fixture URL, and the explicitly distinct
   read-only/comparison capability declaration. Only reviewed Selection/Combo/Tab
   `state.value` fields may translate their proven opaque selected-item reference
   through that table. Never substitute edit/range/arbitrary values, names,
   unknown roles or unmatched strings. A missing/duplicate inverse entry fails.
   Do not mask focus or arbitrary envelope/semantic fields. Do not hide
   missing/extra semantic nodes, weakened states or failed cases by broad
   normalizers. Independently read fixture state after setup as a comparison
   oracle; no oracle value is input to capture/projector.
   Verifier-negative mutations must reject missing/extra/duplicate subjects,
   wrong names/roles/states/descriptors/schemas, arbitrary selector-looking
   textbox values, inverse collisions or missing relations, unexpected focus
   and extra fields. The fixed envelope translation checks allowed values and
   live-source provenance; it is not permission to replace arbitrary envelopes
   with the expected snapshot. Read-only actions[] and private descriptor
   catalogs are separate outputs with distinct exact comparison assertions.
5. Add separately captured expanded ComboBox popup-wrapper/container evidence
   before collapse, plus collapse/fresh-membership invalidation. It is extra
   P4.3 evidence, not an invented change to accepted P4.2 goldens.
6. Validate each actual read-only snapshot, internal comparable snapshot and
   snapshot-response envelope through unchanged core/protocol validators.
   Include source-attributable redaction scans and exact retained output bytes.
   A development envelope validator does not establish a deployed protocol host.
7. Obtain first/repeat real captures serially with first-failure stop, no hidden
   reruns, retries or budget changes; preserve all partial/failure artifacts.
8. Run focused tests, type/contract/native-package/P4.2 canonical checks and
   existing full/browser/conformance/audit gates on the final frozen candidate.
   Record actual terminal results, source pin and independent artifact review.
9. Record a separate limited S2 decision only after the above evidence/reviews.
   All seven real action effects/policy/confirmation, lifecycle/races/events/
   replay/cancellation, actual OS permission/session negatives, P4.4 comparison
   and full P4.3/Phase 4 completion remain later unchanged obligations.

Model-facing input now changes, unlike S1. This slice may claim deterministic
schema/golden conformance only. Before any claim of model understanding or
task success, assess/freeze a separate evaluation dataset/method and execute
its actual authorized provider calls; neither a golden match nor agent prose
supplies model-evaluation proof.

## Primary API basis and rollback

[Microsoft explicit current property reads](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.automationelement.getcurrentpropertyvalue?view=windowsdesktop-10.0)
distinguish unsupported/default substitution and note that current values can
change after a read. [Microsoft selected-item retrieval](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionpattern.selectionpatterninformation.getselection?view=windowsdesktop-10.0)
returns provider elements, with a default empty collection. Our additional
membership, unknown-state and authority restrictions are conservative design
policies, not security guarantees furnished by those APIs.

[Microsoft SelectionProperty](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionpattern.selectionproperty?view=windowsdesktop-10.0)
and [SelectionContainerProperty](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionitempattern.selectioncontainerproperty?view=windowsdesktop-10.0)
identify the selected peers and their container; these provider relationships
still require our separate current native/ancestry fences.
[Microsoft owned-thread window enumeration](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumthreadwindows)
allows a callback to stop enumeration. Its return value alone cannot distinguish
our budget stop from an empty thread; track explicit callback state and refuse
incomplete enumeration. [GetWindow relationships](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow)
define owner and first-enabled-popup lookup, not unique modal admission.

Disable/remove only this isolated candidate through scoped version-control
changes, retaining failures, review and golden history. Never remove user data
or broaden OS permissions to obtain a pass. Disclosure, unprovable membership,
source/evidence drift, missing real-host proof or unresolved Critical/High
findings stop acceptance; they do not silently reduce the project goal.
