# P4.3 S2 — deterministic capture foundation increment

Status: implementation candidate on 2026-10-04; independent source review pending.
This is a subset of the [accepted S2 entry](../reviews/p4.3-s2-entry-2026-10-04.md),
not S2 native execution/acceptance, full P4.3 or Phase 4 exit. All22 real golden

## Implemented boundary

The separate `CaptureHarness` has no UIA dependency, native entry point, fixture
launcher, mutation, model input, network endpoint or public npm export. Its only
CLI mode is `--unit`. The cached SDK launcher builds this isolated project and
starts only its owned30-second unit worker, never the WPF fixture. It installs
nothing and does not change S1 or accepted P4.2 sources/goldens/validators.

- Bounded immutable copied observations and structural graph checks.
- Explicit unknown/sensitive content gate; pre-read forbidden data is refused.
- Reviewed type/container/pattern qualification; ambiguity before filtering;
  unreviewed structural wrappers remain private.
- Literal names/values, finite observed range descriptors, explicit enums,
  distinct missing/false states and opaque selected-item references.
- Distinct model-facing actions-empty snapshots and private comparable metadata.
- Stable per-generation random IDs, locally monotonic semantic revisions,
  retirement, failure/disposal invalidation and bounded cumulative issued IDs.
- Capped UTF8 encoding before CreateNew publication; strict bounded byte parser,
  bijective inverse comparator and unchanged core/native protocol admission.

Actual C# unit serialization is piped to the separate Node validator, including
the model-facing and comparable snapshots. JS golden-shaped mutation fixtures
are deliberately synthetic verifier inputs, **not C# collector or OS evidence**.
They test all22 main and both modal semantic shapes without supplying oracle
values to the C# projector. The unit CLI prints only the compact validated
summary after the cross-runtime check; it does not expose the private inverse
table as a model-facing interface.

## Window-family clarification proposed for actual source review

The frozen S2 design has seven semantic pattern families, while the accepted
P4.2 raw manifest additionally lists WindowPattern for its two Window subjects.
This increment's trusted Window definition uses an explicitly admitted current
Window root/lifetime supplied by the **future collector**, not an eighth semantic
pattern and not a raw WindowPattern-presence assertion. Its core projection has
no Window descriptor. `AdmittedWindowRoot` in synthetic DTO tests is a test input,
not proof of OS authorization. This distinction must receive actual independent
review and a separately recorded delegated clarification before native use;
the frozen S2 design/report bytes are not silently rewritten.
Every additional copied graph root must independently carry a trusted
`AdmittedGraphRoot` proof from the future OS collector; a selected-container
reference cannot substitute for it. The synthetic popup vector marks this
explicitly and an unadmitted auxiliary-root relation is a rejection test.

## Verification and limitations

Commands (run heavy suites serially):

```powershell
pwsh -NoProfile -File scripts/run-p4.3-capture-unit.ps1
node node_modules/vitest/vitest.mjs run test/p4.3-capture.test.ts --pool=vmThreads --maxWorkers=1 --no-file-parallelism --isolate=false
```

The first JS run failed during immutable oracle-source verification because
Vitest's default beforeAll hook budget was10 seconds; no assertion ran and no
native worker launched. The source-pinning hook now explicitly uses the existing
repository JS test budget30 seconds, without changing any10-second observation,
30-second owned unit worker or240-second native worker limit. Retain this failed
run separately from later pass evidence; it is not a native repeat/retry.

Deterministic DTO graph checks do not prove current provider safety, ancestry,
selected-container admission or native popup uniqueness. The copied observation
constructor accepts trusted internal data; it cannot authorize a caller-selected
PID/HWND/application. A fresh projector stopwatch is only a deterministic
projection cap. The future collector must supply **one shared** capture budget
across OS admission, both enumeration passes, all tree/auxiliary reads, copied
text and fences, before calling the pure projector. No collector exists yet.

CreateNew here assumes a launcher-admitted owned output directory; no CLI accepts
an output path. Encoding caps bound managed emitted data, not provider/COM getter
allocation or atomic filesystem publication. Sequential future provider reads
are not atomic snapshots/ABA proof. Synthetic generation labels do not prove
real reset/window/process fences. Development envelopes exercise validators,
not deployed host negotiation. Golden parity does not prove model comprehension.
