# P4.3 window handle read context investigation

Date: 2026-10-14, Asia/Bangkok.
Status: Proposed investigation design; no implementation or native entry.
Owner: `/root` under existing delegated review authority.

## Problem and outcome

The [original R1 first negative](../evidence/p4.3-r1-native-first-failure-2026-10-14.md)
establishes `initial/setup/window-handle/not-supported/InvalidObservation`.
It cannot distinguish root proof, discovery member, fresh target/ancestor,
selected container or fence reads. A safe remediation must first distinguish
the existing source callsite without inferring an element's ownership from a
missing property. Toolchain provisioning and human Desktop readiness do not
answer that question.

## Proposed bounded diagnostic method

1. Preserve every R1 source/input/artifact/report/freeze/entry and the original
   negative. Use a separate explicitly fixed candidate/profile; never change
   R1 pins to bless different bytes or make its admitted reader stop working.
2. Add only a closed source-owned enum indicating the already executed
   window-handle read's call context. Labels are source callsites, not provider
   type/name/value/runtime ID, HWND, PID, identity or an inferred OS cause.
3. Thread the passive context through existing required reads and the existing
   immutable primary-failure latch. Do not add a UIA/OS getter, walk, probe,
   retry, additional provider invocation or diagnostic permission.
4. Keep the exact original typed-read/deadline/NotSupported refusal behavior.
   No NotSupported-to-zero conversion, default substitution, skipped boundary,
   alternate ancestry authorization, weakened root proof or new pattern access.
5. Use a separately fixed private negative format/admitted reader with closed
   field/context/stage combinations, original-byte/digest/path checks, original
   4096-byte/depth/token/string caps, bounded output and no public protocol change.
   Reject missing/unknown/duplicate/forged contexts; non-window-handle failures
   must not acquire a misleading context. The first actual primary stays latched.
6. Pure fault injection must prove that annotating each context does not call
   the getter again, change its result/exception, authorize a later operation,
   overwrite an earlier failure or expose provider contents.
7. Review this design before source changes. Review exact new source, qualify
   actual committed builds/closure and obtain a separate operator entry before
   one original native pair. Preserve all original counts/budgets/guards and
   stop at its first failure; a diagnostic label is not an S2 success result.

This is investigation, not yet a metadata-handling/ownership refinement.
After actual context evidence, propose any semantic fix separately with its
positive ownership proof, adversarial cases and required ADR/entry review.
Do not presume that the failing peer is a windowless structural wrapper.
