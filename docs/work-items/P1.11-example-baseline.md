# P1.11 — Document Approval Example and Phase 1 Baseline

Status: In implementation

Phase: 1 — Core contract and DOM reference

Required approver: Repository maintainer

## Problem and user outcome

The core has isolated contract tests but no complete reference workflow or
recorded efficiency baseline. Maintainers need a runnable example showing how a
human and an agent share application state, plus honest measurements that later
phases can compare without importing a model dependency into Phase 1.

## Scope

- runnable document-approval HTML example using the package build;
- shared human/agent business operation and visible final state;
- typed consequential domain action covering the complete safety lifecycle;
- deterministic runner and 25-repetition measurement harness;
- context bytes/token estimate, interaction steps, completion, wrong action,
  confirmation, unauthorized-action, secret-leak, and latency metrics;
- frozen method ADR, automated tests, baseline report, and README guidance.

## Non-goals and prohibited changes

- no model/provider call, prompt benchmark, vision run, or claim of model quality;
- no browser/device/production latency claim;
- no Phase 2 exporter, framework adapter, transport, or package publication;
- no public schema, runtime API, dependency, or package-version change;
- no alteration of Phase 1 target thresholds after observing results.

## Trust boundaries and data classification

The fixture is untrusted page content. Its hidden sentinel is synthetic test
data, not a real secret, and must not enter the snapshot, result, audit stream,
or committed report. Action input remains untrusted and schema-validated. The
authenticated principal, origin, policy, trusted confirmation, precondition,
effect verification, and idempotency boundary stay authoritative.

## Compatibility

This task adds only examples, scripts, tests, documentation, and package scripts.
It does not change exported runtime behavior or serialized `0.1` contracts. The
example imports the built public package entry point.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | A fresh checkout can build and run the document-approval example through the public package entry point. |
| AC-02 | Human and agent paths invoke the same business operation and produce the same visible `Approved` state. |
| AC-03 | The agent path discovers typed metadata and completes observe → two required toggles → confirmed `approve_document`. |
| AC-04 | Approval passes principal/origin policy, one trusted confirmation, immediate precondition, effect verification, keyed replay policy, and redacted audit. |
| AC-05 | Snapshot, result, events, and report contain zero hidden-sentinel occurrences. |
| AC-06 | The frozen harness records 25-repetition completion, steps, wrong actions, confirmations, unauthorized consequential actions, and latency. |
| AC-07 | Context records serialized full-DOM and semantic UTF-8 bytes plus clearly labeled `ceil(bytes / 4)` token estimates. |
| AC-08 | Report records commit, fixture hash, environment, timestamp, raw samples, and latency scope and is labeled `deterministic-scripted-no-model`. |
| AC-09 | Automated tests cover example contract, lifecycle, parity, redaction, and metric calculations. |
| AC-10 | Existing typecheck, build, tests, audit, package import, and package dry-run remain green. |

## Design

ADR 0005 freezes the measurement method. The fixture contains normal layout
noise and one hidden synthetic sentinel. The reusable workflow module receives
the package factory, wires the shared application operation, and exposes human
and scripted agent runners. The measurement CLI imports `dist/index.js`, creates
an isolated jsdom per repetition, and emits JSON to standard output. Pure metric
helpers have deterministic unit tests.

## Rollback / disable strategy

Revert the P1.11 commits or stop invoking the opt-in example/baseline scripts.
No runtime behavior, persisted data, schema, or published artifact changes.
