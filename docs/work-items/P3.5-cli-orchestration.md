# P3.5 — CLI Orchestration

Status: Implemented and verified on 2026-09-20

Phase: 3 — Ecosystem, reliability, and evaluation

Required approver: Repository maintainer

## Problem and user outcome

Developers and CI need one deterministic command-line entry point to inspect,
validate, compare, record, replay, and evaluate Dual Surface artifacts without
writing transport-specific scripts.

## Dependencies and scope

P3.5 depends on P3.3 and P3.4. It adds an optional CLI library and packaged
executable with `inspect`, `validate`, `diff`, `record`, `replay`, and
`evaluate` commands; stable JSON/NDJSON output; documented exit codes; bounded
stdin/file handling; and an explicit trusted local-driver interface.

The initial `evaluate` command will be completed against a deterministic
driver. Real multi-model datasets and evidence belong to P3.8.

## Non-goals and prohibited changes

- no network or provider call, browser launch, navigation, credential loading,
  production connection, daemon, or shell execution by default;
- no implicit overwrite, page-controlled output path, or unbounded stdin;
- no raw secret, stack, prompt, or untrusted page text in diagnostics;
- no mandatory Playwright, MCP, framework, or model-provider dependency for
  root consumers.

## Trust boundaries and data classification

Command arguments, stdin, artifact files, local driver output, and terminal
capabilities are untrusted. A configured local driver is executable trusted
code and must be labeled as such. Machine-readable stdout is a public contract;
diagnostics use stderr and remain redacted.

## Compatibility and rollback

The CLI is additive through a package `bin` and optional library subpath. Root
runtime exports remain frozen. Removing the executable and subpath does not
change application runtime behavior or stored data.

## Acceptance criteria

| ID | Requirement |

| AC-01 | All six commands provide deterministic help, argument validation, machine-readable output, and documented stable exit classes. |
| AC-02 | `inspect` and `validate` recognize supported snapshots, deltas, traces, replay fixtures, and evaluation definitions without executing embedded content. |
| AC-03 | `diff` produces stable output and enforces exact surface/revision compatibility. |
| AC-04 | `record` writes only bounded redacted trace data through an explicit trusted driver and never derives a path from page content. |
| AC-05 | `replay` accepts only reviewed synthetic fixtures and has no live-target mode. |
| AC-06 | `evaluate` reports parsed definitions rejected by schema, digest, budget, or secret controls as an exact semantic-invalid result, and otherwise runs a deterministic driver and emits dimension-level scores without model-based pass/fail judgment. |
| AC-07 | JSON mode reserves stdout for results, stderr for redacted diagnostics, and disables presentation-only noise; evaluation NDJSON is buffered into one stdout sink write. |
| AC-08 | File writes are atomic where supported and refuse overwrite unless explicitly requested. Cancellation leaves no artifact presented as complete. |
| AC-09 | Oversized, malformed, recursive, missing, unreadable, and secret-bearing inputs fail with stable nonzero exits and no stack leakage. |
| AC-10 | The packed executable and optional library import work in isolated consumers on supported Node versions; optional peers remain lazy. |
| AC-11 | Typecheck, build, deterministic, audit, package, contract-freeze, and diff gates pass. |

## Implemented design and evidence

[ADR 0011](../adr/0011-cli-orchestration-boundary.md) freezes the six-command
argument grammar, canonical JSON/NDJSON envelopes, exit table, artifact
registry, deterministic exact-equality evaluation, atomic overwrite rules, and
explicit trusted-driver contract before implementation.

The CLI remains offline and synthetic by default. `record` and `evaluate`
require an explicit local driver and `--trust-driver`; replay cannot accept a
live target. The implementation is commit `6cdb54f`; the contract foundation
is commit `9743e8a`.

The reference Node host uses bounded input, same-directory atomic output,
no-clobber defaults, explicit overwrite rules, protected driver identity, and
abort-aware stdin. Each trusted driver operation runs pinned bytes in a fresh
child process with restricted environment and IPC, bounded output, timeout,
SIGTERM-to-SIGKILL escalation, and parent-side result validation. Evaluation
NDJSON is buffered before one stdout write. A completed record commit remains
authoritative if cancellation arrives afterward.

Evidence was collected on Windows with Node `v24.16.0` and npm `11.13.0`:

| Evidence | Result |
|---|---|
| focused CLI runtime suites | 6 files and 52 tests passed, including driver termination/IPC, atomic I/O, blocked-stdin cancellation, commit-wins, exact output, and orchestration. |
| `npm run test:gate` | 45 files and 521 tests passed with the deterministic VM-thread settings. |
| `npm run contract:check` | Build passed and the Phase 1 contract remained frozen at 32 runtime exports, 6 declaration files, and 5 schemas. |
| `npm run package:check:cli` | Isolated pack/install, runtime/declaration imports, exact five CLI schemas and AJV references, direct executable and npm shim, all six commands, fixtures, peer isolation, allowlist, and leak scan passed. |
| `npm run package:check:trace-replay` | Existing packed trace/replay consumer passed after the additive CLI schema set. |
| `npm audit --json` | 0 vulnerabilities at every severity. |
| `git diff --check` | Passed after fixture EOF cleanup; Windows line-ending notices only. |

Independent security/correctness review found and drove fixes for forced driver
overwrite, unbounded direct IPC, non-terminating children, partial NDJSON,
semantic-invalid exit mapping, cancellation races, blocked stdin, and
post-commit cancellation. Final review confirmed no unresolved Critical, High,
or Medium issue.
