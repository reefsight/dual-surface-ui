# P4.5 — Authenticated Local Native Host

Status: Planned; implementation blocked until P4.4 explicitly selects a native strategy

Phase: 4 — Native surfaces

Required approver: Repository maintainer, technical maintainer, security owner,
and release owner

## Problem and user outcome

An in-process adapter harness is not a safe product boundary. A local agent needs
an authenticated, least-privilege host that owns OS permission, policy, native
identity, revision, replay, audit, and lifecycle state without exposing a remote
service or trusting caller-supplied process/window claims.

P4.5 implements that host only after P4.4 selects its runtime strategy. It uses
protocol 0.1 unchanged and wraps the accepted Windows adapter before macOS parity.

## Entry gate

- P4.1–P4.3 accepted with no unresolved critical/high finding;
- P4.4 explicitly accepted as `rust`, `platform-native`, or `node-native`;
- ADR 0019 accepted with the selected transport/authentication/isolation design;
- exact toolchain, dependencies, local OS APIs, package/sign/update method, and
  supported OS matrix frozen before implementation.

## Scope

- local-only per-user host lifecycle;
- OS-authenticated peer identity and challenge-bound protocol session creation;
- least-privilege adapter process isolation and capability negotiation;
- server-owned surface/process/window/session/policy/confirmation/replay state;
- bounded frame admission, request scheduling, cancellation, event delivery,
  backpressure, idle expiry, reconnect, crash recovery, and clean shutdown;
- redacted security audit records with tamper-evident ordering/digests;
- signed development artifact, deterministic package manifest, SBOM, update and
  rollback design, without public release;
- Windows real-host evidence; macOS host integration remains P4.6.

## Non-goals and prohibited changes

- no TCP/HTTP/WebSocket listener, LAN/Internet exposure, remote control, or cloud relay;
- no static bearer secret in source, arguments, environment, logs, or world-readable file;
- no system-wide service/elevation by default, kernel driver, screen scraping,
  arbitrary input injection, shell, memory access, or unrestricted process enumeration;
- no caller-selected OS user/session, principal, PID, HWND, native selector,
  policy, risk, confirmation, or permission result;
- no silent accessibility permission grant, UAC bypass, secure-desktop action,
  password value access, or cross-user session access;
- no npm-native binary leakage, publication, release tag, production deployment,
  signing credential commit, or automatic update enablement;
- no whole-project migration to the selected native language.

## Authentication and authorization invariants

1. The host creates a per-user local endpoint with restrictive OS ACL/mode before accepting a peer.
2. The host obtains peer identity from the OS transport, never from protocol fields.
3. A fresh unpredictable challenge binds peer identity, endpoint instance, protocol version, and session generation.
4. Successful authentication mints a short-lived opaque `sessionRef`; reconnect creates a new generation and invalidates all old state.
5. Every request rechecks authenticated user/session, capability, admitted application/window, current binding/revision, policy, confirmation, and permission.
6. Authorization is least privilege per action/surface; discovery does not imply mutation.
7. Authentication/authorization/permission loss closes or invalidates the affected session without catalog disclosure.
8. Replay scope is per authenticated session and trusted principal; request IDs and idempotency keys alone never grant authority.

## Lifecycle and delivery invariants

- one host instance per interactive user/session unless a later ADR proves another model;
- inherited handles, child processes, filesystem access, environment, working
  directory, and outbound network are minimized and documented;
- frames are length-bounded before allocation and parsed by the accepted strict parser;
- queues have fixed per-session/global budgets and fair scheduling;
- crash/restart cannot reuse session/surface references or report an uncertain mutation as cancelled;
- audit output is bounded, redacted, append-ordered, rotated, and unavailable as an authority channel;
- update verifies signature, version/channel policy, rollback compatibility, and
  protocol support before replacement; failure retains the last known-good artifact;
- uninstall removes host-owned artifacts without deleting user data outside its reviewed directory.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | P4.4 contains an explicit accepted runtime decision before host source/toolchain work begins. |
| AC-02 | The endpoint is local-only and per-user with restrictive OS ACL/mode; remote transports and wildcard listeners are absent. |
| AC-03 | Peer identity comes from the OS transport and a fresh challenge-bound handshake; protocol fields cannot self-assert identity. |
| AC-04 | Authentication failure, capability/version failure, permission loss, user/session mismatch, or stale endpoint instance discloses no catalog and fails closed. |
| AC-05 | Reconnect/restart mints a new generation and invalidates sessions, surfaces, revisions, confirmations, cancellations, replay entries, and pending events. |
| AC-06 | Every action reauthorizes trusted identity, admitted application/window, current element/revision, policy, confirmation, permission, and expected effects immediately before mutation. |
| AC-07 | Static bearer secrets and credentials are absent from source, args, environment, files, logs, errors, traces, fixtures, package, and audit evidence. |
| AC-08 | The host runs without elevation/system service by default and documents minimal process/filesystem/network/child-process privileges. |
| AC-09 | Frame, connection, session, queue, request, event, audit, time, memory, and concurrency budgets reject overload before unbounded allocation/work. |
| AC-10 | Backpressure, fairness, idle expiry, cancellation, disconnect, crash, and restart have deterministic fail-closed tests. |
| AC-11 | Uncertain or committed mutations return authoritative outcome/resync semantics and are never converted into false cancellation or retry success. |
| AC-12 | Audit records are stable, bounded, redacted, ordered, integrity-linked, and contain no raw native handle, secret, private application text, or exception. |
| AC-13 | Signed development packages have a frozen manifest/SBOM/provenance; signing material remains outside the repository and test evidence. |
| AC-14 | Update and rollback tests reject bad signature, downgrade, incompatible protocol, interrupted replacement, and tampered artifact while retaining last known good. |
| AC-15 | Installer/uninstaller tests operate only inside exact reviewed directories and leave unrelated user/system data untouched. |
| AC-16 | Windows real-host latency, memory, startup, throughput, crash recovery, and long-run stability meet P4.4 accepted budgets. |
| AC-17 | Existing full/browser/conformance/contract/audit/package gates pass and npm contains no host/native artifact. |
| AC-18 | Independent authentication, authorization, isolation, protocol, package/sign/update, and operations reviews report no unresolved critical/high finding. |

## Rollback and compatibility

The host remains a private development artifact until Phase 4 Exit approval.
Rollback restores the last signed compatible artifact and creates a fresh
endpoint/session generation. It never reuses credentials or native references.
Host updates may add supported protocol versions but cannot mutate frozen 0.1;
incompatible behavior requires a new protocol/schema/fixtures and migration ADR.
