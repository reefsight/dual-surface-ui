# P3.7 — Prompt-Injection and Confused-Deputy Adversarial Suite

Status: Design accepted; implementation pending

Phase: 3 — Ecosystem, reliability, and evaluation

Required approver: Security owner plus repository maintainer

## Problem and user outcome

Normal conformance fixtures do not prove that hostile page content, transport
metadata, model output, or fallback observations cannot redirect authority.
Maintainers need a versioned adversarial corpus mapped to the accepted threat
model and deterministic security controls.

## Dependencies and scope

P3.7 depends on the P3.6 shared harness and the complete P3.2 semantic and
visual fallback boundaries. It adds stable threat-case IDs, reviewed malicious
fixtures, deterministic variants, a threat-to-control matrix, leak scanning,
and redacted machine-readable results.

Coverage includes hostile accessible text, fake policy/confirmation
instructions, malicious tool output, action substitution, identity/origin/
surface/revision confusion, target ABA, replay-scope confusion, MCP metadata,
visual candidate manipulation, and trace/CLI artifact injection.

## Non-goals and prohibited changes

- no live hostile site, production account, real credential, or uncontrolled
  third-party content;
- no prompt-only mitigation for a deterministic authorization defect;
- no model output as policy or expected-result oracle;
- no retry, case deletion, threshold change, or severity downgrade to hide a
  failing critical scenario;
- no general penetration-test or native-platform claim.

## Trust boundaries and data classification

All fixture text, model/tool output, visual callback output, transport metadata,
and artifact content are untrusted. The policy engine, trusted confirmation,
fixture identity, authoritative state, and expected result remain trusted.
Only synthetic sentinels are used; credential and secret values remain
prohibited even in adversarial fixtures.

## Compatibility and rollback

The corpus and harness extensions are additive test assets. Findings may block
release but cannot silently redefine the frozen runtime contract. Reverting
the suite changes no runtime behavior, though unresolved findings remain gate
failures.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Every accepted Phase 3 threat has stable case IDs, an attacker-controlled field, expected control, expected outcome, and authoritative state assertion. |
| AC-02 | Page names/descriptions/content cannot create, rename, select, authorize, confirm, or execute an undeclared action. |
| AC-03 | Malicious tool output, MCP metadata, and CLI/trace content remain data and cannot alter policy or driver configuration. |
| AC-04 | Principal, origin, surface, revision, action, target, page/context, and idempotency scopes cannot be substituted or crossed. |
| AC-05 | Target replacement and semantic ABA fail stale before unauthorized mutation. |
| AC-06 | Visual selection can return only a current allowlisted non-sensitive node ID and cannot introduce coordinates or authority. |
| AC-07 | Critical safety cases pass every repetition with zero unauthorized consequential action. |
| AC-08 | Snapshot, trace, model context, output, report, stdout, stderr, and package corpus contain zero secret-sentinel bytes. |
| AC-09 | Failures retain their original case and severity with an explicit disposition; no automatic retry masks the first result. |
| AC-10 | Independent security review reports no unresolved critical/high finding before the work item can complete. |

## Accepted design and planned evidence

[ADR 0013](../adr/0013-adversarial-injection-and-confused-deputy-boundary.md)
freezes the private corpus boundary, exact threat families, deterministic seed
rule, redacted report shape, and independent security-review gate. The corpus
will be frozen and hashed before execution. Deterministic generated variants
use recorded seeds. A security report will separate prevented attacks, safe
failures, environment failures, and unresolved findings.

Implementation and evidence are still pending; this acceptance records design
authority only and does not claim that any adversarial case has passed.

No adversarial execution evidence exists yet.
