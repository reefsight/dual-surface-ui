## Constructor-only passive refusal observation

Use two private closed enums, AdmissionCheck and AdmissionGuard, declared in
the existing admission source file. The fixed suite may supply an internal
optional observer accepting only those two enum values. It is not public,
client-selectable, a generic operation executor or a source of OS authority.
Existing standalone callers with no observer retain the same refusal behavior.

The observer is enabled only while this specific constructor runs, and cleared
in constructor finally on success or refusal. Subsequent Observe/context/peer
checks and cleanup have no observer capability and remain coarse as before.
Window-replacement construction is eligible only within its existing setup
context, and process-restart construction only within its existing startup
context. No additional constructor or OS admission is performed for diagnostics.

Set check context only from static host constructor/helper callsites immediately
before their unchanged operations. On an existing explicit Unavailable guard,
notify once with the current static check plus that static guard group, then
throw the same CaptureException(Unavailable) unconditionally. Guard expressions,
short circuiting, allocation bounds, native calls, reads and pre/post time checks
stay unchanged. A compound guard identifies a group, not which Boolean operand
or native value was rejected. SDK/managed exceptions and deadline refusals not
converted by existing Refuse retain their original coarse classification; do
not infer a guard tag merely from the last entered check.

The optional observer must be passive and synchronous. Its exception cannot
replace the original guard: catch/withhold observer errors and still throw the
original closed refusal. The suite observer validates the enum pair before an
atomic immutable first-primary latch. Invalid observation cannot partially set
diagnostic fields or authorize continuation; fall back only to the unchanged
coarse refusal, never an admission/safety default. Once a primary exists, ignore
later observer notifications. No event timestamp, duration, successful-check
trace, result Boolean, exception object or native data is passed or retained.
The callback performs only closed pair/context validation and the single
immutable assignment: no IO, clock/deadline calls, logging or native/provider
operation, including on invalid or already-latched input.

Pure tests may invoke an isolated notification helper with synthetic enum values;
they must not construct a real Process/admission or query tokens/desktops/UIA.
No property or token/desktop diagnostic probe runs after a refusal. Existing
required resource cleanup remains the only post-refusal native activity.

## Exact check and guard grammar

The check literals and their only allowed guard literals are:

| admissionCheck | Allowed admissionGuard |
| --- | --- |
| subject-token | token-open, token-elevation-uiaccess, token-buffer-bound, token-buffer-result, token-integer-shape, token-sid-size, token-sid-pointer, token-sid-body |
| worker-token | same eight token guards |
| current-subject-token | same eight token guards |
| process-liveness | liveness |
| token-context | identity-session |
| session-active | session-query-state |
| window-station | name-query, name-value |
| worker-desktop | name-query, desktop-name-or-null, desktop-input |
| input-desktop-open | input-open |
| input-desktop | name-query, desktop-name-or-null, desktop-input |
| anchored-main | window-boundary |
| main-desktop | name-query, desktop-name-or-null, desktop-input |

Here token-elevation-uiaccess preserves the original combined zero check for
integer kinds20/26; token-buffer-bound/result preserve the original capacity
and native buffer-result guards; token-integer-shape identifies the existing
used==4 refusal; token-sid-size/pointer/body preserve the existing size query,
pointer/offset/header and subauthority/layout groups. No SID kind, bytes or value
is serialized. name-query groups the existing null-handle, query/result/size/
terminator or null-string refusal; name-value denotes an already-computed
required station-name comparison. desktop-name-or-null instead preserves the
existing compound `desktop == 0 || ObjectName(desktop, budget) != "Default"`:
a zero handle short-circuits without any name observation. That group must not
be relabelled as a measured name mismatch, split into new reads or evaluated
again for diagnostics. An ObjectName refusal during the right-hand operand
retains its own name-query label. desktop-input groups the existing information query/
size/flag condition. Input-open, liveness, identity-session, session-query-state
and window-boundary likewise preserve their existing guard groups exactly.
The group is a source-derived assertion, not an underlying OS cause.

## New closed private failure kind

Use fixed failure.json and all D1 owned output/canonical ancestor/opened regular
single-link/CreateNew/publication/reader constraints. D2 has schemaVersion0.1
and a distinct kind `p4.3-native-capture-suite-d2-failure`; it is not an extension
silently accepted by the original D1 twelve-key parser.

Its exact fourteen required keys are D1's twelve, plus admissionCheck and
admissionGuard, each explicit null or its closed literal above. Both are null
together, or both present with a valid table pair. A non-null pair is legal only
for classification guard-refused/code Unavailable and either bootstrap/startup/
setup-admission, process-restart/startup/setup-admission, or
window-replacement/setup/setup-admission. No other case,
stage, site, SDK exception, timeout, later cleanup or capture may claim these
constructor-only fields. Preserve every existing D1 case/stage/site/class/code/
cleanup/timestamp/digest cross-field condition. A callback from an unexpected
host context is withheld and the original guard remains a coarse failure.

Primary immutable tuple carries both optional fields atomically; ordinary D1
latch paths initialize both null. Secondary cleanup code cannot replace the
pair. Production recordedAt is still actual UTC serialization time after the
existing cleanup attempt, not an initial failure timestamp or duration.

Retain4096 original bytes,depth2,token32,string128,strict UTF8/no BOM/decoded
duplicate/UTF16/trailing-JSON/type checks. A valid fourteen-field flat record
uses30 tokens, so no parser/resource cap needs widening. D2 parser validates
the exact kind/keys, new pair relation and actual new pins before emitting only
the record, raw original-byte SHA256 and nativeAccepted:false. It never reads
partial recorder/provider/capture/report content or inventories the run.
The unchanged success verifier rejects failure.json and still requires the
original132 artifacts/report/records child plus independent first/repeat proof.

Keep the original D1 parser as its exact separate negative-only contract. A new
parseNativeSuiteD2Failure path may reuse the bounded flat scanner and single-file
reader without making D1 accept the extra keys/kind. The production CLI admits
only the new fixed D2 freeze first and dispatches D2, never guesses a kind from
untrusted bytes, falls back to D1 authority or offers caller-selected review pins.
Historical D1 bytes remain immutable and bound by their actual prior reviews;
later changed working-tree source/binaries cannot claim the old admission proof.

   re-review findings, then record a separate docs-only implementation entry.

   changed boundaries and obtain actual three-role source approval. Run all

   remain failures; optional historical Chrome-profile failure is not relabelled.

   evidence requires a real host/session/security change or new authority,

   compatibility fix requires its own reviewed design/evidence; this proposal
   does not pre-authorize a fix to an unmeasured guard.
