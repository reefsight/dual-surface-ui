# P2.6 — Trusted Domain-Action Annotations

Status: Implemented and verified on 2026-09-18

Phase: 2 — Web standards and framework adoption

Required approver: Repository maintainer

## Goal and outcome

Applications need one trusted place to describe a business action and then
reuse that exact semantic definition across core, framework lifecycle adapters,
and WebMCP. The additive `dual-surface-ui/domain` package entry point provides
that authoring boundary through `defineDomainElement()`.

The compiler returns:

- `definition`, a detached `AgentElementDefinition` for `surface.register()`
  and the React, Angular, or Vue lifecycle adapters;
- `webMcpBindings`, an explicit allowlist containing only actions with a
  developer-owned `webMcpName`.

This layer does not execute actions. Core remains responsible for revision and
input validation, policy, confirmation, preconditions, handler execution,
output validation, effect verification, replay protection, structured
failures, and redacted audit events.

## Public API

```ts
export interface DomainActionAnnotation extends AgentActionDefinition {
  description: string;
  risk: AgentRisk;
  handler: NonNullable<AgentActionDefinition["handler"]>;
  webMcpName?: string;
}

export interface DomainElementAnnotation {
  id: string;
  description?: string;
  actions: Record<string, DomainActionAnnotation>;
}

export interface CompiledDomainElement {
  definition: AgentElementDefinition;
  webMcpBindings: readonly WebMcpToolBinding[];
}

export function defineDomainElement(
  annotation: DomainElementAnnotation,
): CompiledDomainElement;
```

The transport-specific `webMcpName` and `webMcpBindings` names are deliberate:
they do not imply that an MCP, CLI, or native exporter has been implemented.
`webMcpName` is removed from the core definition and never appears in a
snapshot.

## Trust and data-flow boundary

Trusted inputs are static application-owned identifiers, descriptions, risks,
schemas, preconditions, effects, handler references, and explicit WebMCP
names. DOM text, accessible names, form values, URLs, user content, model
arguments, and handler output are untrusted.

The compiler captures every own data property once. It rejects accessors,
symbols, non-enumerable fields, exotic prototypes, sparse arrays, cycles,
non-finite numbers, unknown strict-domain keys, and malformed schemas. It does
not call getters or `toJSON()`. Captured schemas and identifier arrays are
detached, and the complete compiled result is frozen recursively.

Core registration keeps its frozen `0.1` acceptance and execution timing while
using a separate safe detached clone that does not invoke metadata accessors.
Strict limits and schema preflight apply when the application opts into
`defineDomainElement()`; direct root definitions retain the existing
execution-time schema failure behavior. Core does not depend on the optional
domain package or WebMCP exporter.

## Strict authoring rules

- An element has a stable 1–128 character identifier and 1–64 actions.
- Action names are stable identifiers of at most 64 characters, matching the
  frozen `0.1` snapshot schema.
- Every action has a non-blank trusted description, explicit risk, and handler.
- A non-read action declares at least one effect.
- A consequential or destructive action sets `requiresConfirmation: true`.
- Preconditions and effects contain at most 32 unique stable identifiers each.
- Descriptions contain at most 500 characters and no control characters.
- Input and output schemas are JSON-safe plain data, compile under the core
  JSON Schema 2020-12 validator, and stay within depth, node, and serialized
  length budgets.
- An exposed input schema must also satisfy the WebMCP portable-schema subset;
  unresolved references and dynamic references fail during compilation.
- Credential-risk actions can remain core-local but cannot set a WebMCP name.
- Duplicate WebMCP names within one compiled element fail closed.

Risk is a trusted security assertion. The compiler cannot prove that a
supposedly read-only handler is pure, so code review and application tests must
verify that assertion. WebMCP annotations remain advisory; core policy is the
authority.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | `dual-surface-ui/domain` is additive and does not alter the frozen root contract. |
| AC-02 | One capture produces the exact core definition and explicit WebMCP allowlist without rereading untrusted annotation values. |
| AC-03 | Every strict action requires a trusted description, explicit risk, and handler. |
| AC-04 | Non-read actions without effects and consequential/destructive actions without confirmation fail closed. |
| AC-05 | Only `webMcpName` creates a binding; it never enters the core definition or snapshot. |
| AC-06 | Credential exposure and duplicate WebMCP names fail closed. |
| AC-07 | The strict compiler rejects invalid identifiers, risk, idempotency, unknown fields, and resource-limit violations before its output can be registered. |
| AC-08 | Malformed, cyclic, accessor-based, sparse, exotic, and non-finite schemas fail without executing application code. |
| AC-09 | The returned definition, schemas, arrays, bindings, and result are detached and recursively frozen. |
| AC-10 | The compiled definition follows the existing core order: input, policy, confirmation, preconditions, handler, every effect, output/result. |
| AC-11 | Keyed retries use existing replay protection and do not invoke the handler twice. |
| AC-12 | DOM, ARIA, URL, user, and model content cannot change trusted tool metadata. |
| AC-13 | React, Angular, and Vue accept the same compiled definition without framework-specific semantics. |
| AC-14 | Packed domain-subpath and root-without-optional-peers consumers pass. |
| AC-15 | Full tests, frozen-contract check, dependency audit, package inspection, and diff check pass. |

## Negative and threat cases

| Case | Expected disposition |
|---|---|
| Getter in element, action map, action, schema, or identifier array | Reject without invocation. |
| Proxy throws a secret-bearing error | Normalize to a fixed package error without leaking the value. |
| Own `__proto__` schema key | Preserve as own data on a null-prototype clone; never mutate the clone prototype. |
| Schema cycle, excessive depth/nodes/length, sparse array, or non-finite number | Reject before policy, handler, or DOM mutation. |
| Misspelled security field such as `requireConfirmation` | Reject as an unknown strict annotation field. |
| Credential action with `webMcpName` | Reject compilation. |
| Two actions with the same `webMcpName` | Reject compilation. |
| `$ref` or `$dynamicRef` in an exposed input schema | Reject as outside the portable WebMCP subset. |
| Source metadata mutated after compilation | No change to compiled definition or binding. |
| Compiled nested schema mutation attempted | Throw or remain unchanged because the graph is frozen. |
| Hostile visible label | Keep trusted binding name and description unchanged. |

## Package and compatibility boundary

The new `./domain` export emits ESM and declarations under `dist/domain` and
adds no dependency or optional peer. It is not re-exported from the root. The
root must retain 32 runtime exports, six frozen declaration hashes, five
schema hashes, contract version `0.1`, package version `0.1.0`, serialized
fields, error codes, registration acceptance, failure timing, and existing
default policy behavior.

The compiled `definition` is deliberately the existing public core type, so
framework adapters need no new dependency and no semantic translation.

  69/69 tests.
- `npm run typecheck` passed.
- `npm run test:gate` passed 20 files and 224 tests.
- `npm run contract:check` preserved 32 root runtime exports, six frozen
  declaration hashes, five schema hashes, and contract version `0.1`.
- A fresh packed consumer installed with `--omit=peer`, passed strict
  TypeScript checking, imported both root and `dual-surface-ui/domain` at
  runtime, and confirmed React, Vue, and Angular were absent.
- `npm audit --json` reported zero vulnerabilities.
- `npm pack --dry-run --json` contained 84 intended entries, including
  `dist/domain`, in a 60,344-byte tarball (310,326 bytes unpacked).
- `git diff --check` passed with line-ending warnings only.
- Independent final security review found no remaining commit blocker.

## Non-goals

- No second executor, policy engine, handler registry, or verification API.
- No automatic tool export or action inference from DOM/framework trees.
- No handler purity inference and no trust in handler output for verification.
- No MCP, Playwright, CLI, or native transport implementation.
- No root schema, serialized field, error-code, or version change.

## Rollback

Remove the `./domain` package export and `src/domain` entry point. The internal
safe registration capture can remain as core hardening. Existing core,
WebMCP, React, Angular, Vue, and human UI behavior need no data migration.
