# P3.1 — MCP Snapshot Resource and Typed Action Exporter

Status: Design accepted; implementation in progress

Phase: 3 — Ecosystem, reliability, and evaluation

Required approver: Repository maintainer

## Problem and user outcome

Applications already expose a deterministic Dual Surface UI snapshot and safe
action lifecycle in-process and through WebMCP. Agents outside the page need a
standard MCP endpoint that can read a secret-safe current snapshot and invoke
only explicitly approved actions without moving policy or business logic into
the transport adapter.

P3.1 adds a transport-neutral MCP server boundary. The host chooses and secures
the transport; the package owns only current-surface resources, typed action
tools, authorization hooks, projection, and delegation to the core runtime.

## Scope

- additive `dual-surface-ui/mcp` package subpath;
- dedicated official SDK v2 low-level `Server` for one surface;
- one private zero-TTL current-snapshot resource under a server-minted opaque
  `surfaceRef` URI;
- per-request authorization for resource/tool list, snapshot read, and tool
  invocation;
- explicit trusted tool bindings and deterministic catalogs;
- strict revision/input/idempotency envelopes using bounded portable schemas;
- execution through `performSafe()` and projected structured outcomes;
- cancellation before core execution, idempotent disposal, and retained-
  callback fail-closed behavior;
- legacy linked-transport and modern 2026-07-28 no-socket SDK integration
  evidence;
- packed-consumer import evidence for the optional subpath.

## Non-goals and prohibited changes

- no generic action dispatcher or automatic export of inferred DOM actions;
- no credential-risk action, caller-selected surface/target/action/risk,
  caller-provided principal/origin, or `confirmed` argument;
- no direct handler or DOM execution, duplicated policy, or business rule;
- no raw snapshot serialization, raw page URL in a resource URI, filesystem
  resolution, URL fetching, SSRF path, shared cache, or immutable-history claim;
- no HTTP/stdio listener, OAuth/TLS/CORS/Origin/rate-limit implementation, MCP
  elicitation, prompts, sampling, roots, tasks, or bearer-token passthrough;
- no Playwright fallback, CLI, trace/replay, delta snapshot, model eval, or
  Phase 4 native code;
- no root export, frozen schema, package version, or release change.

## Public API candidate

```ts
import type { Server, ServerContext } from "@modelcontextprotocol/server";

export interface McpSurface {
  snapshot(): AgentSnapshot;
  performSafe(request: AgentActionRequest): Promise<AgentActionOutcome>;
}

export interface McpToolBinding {
  name: string;
  description: string;
  elementId: string;
  action: string;
}

export type McpAccessOperation =
  | "resources.list"
  | "resources.read"
  | "tools.list"
  | "tools.call";

export interface McpAccessRequest {
  operation: McpAccessOperation;
  surfaceRef: string;
  toolName?: string;
  context: ServerContext;
}

export interface McpServerOptions {
  serverName: string;
  serverVersion: string;
  surfaceRef: string;
  bindings: readonly McpToolBinding[];
  authorize(request: McpAccessRequest): boolean | Promise<boolean>;
}

export interface AgentSurfaceMcpServer {
  readonly server: Server;
  readonly snapshotUri: string;
  readonly toolNames: readonly string[];
  dispose(): Promise<void>;
}

export function createAgentSurfaceMcpServer(
  surface: McpSurface,
  options: McpServerOptions,
): AgentSurfaceMcpServer;
```

The final names may change during type-level integration with SDK v2, but the
authority and data-flow boundaries above are fixed.

## Wire design

### Snapshot resource

The URI is `dual-surface://surface/<surfaceRef>/snapshot`, where `surfaceRef`
is required to match the existing opaque URL-safe identifier budget. Every
authorized read captures current state, replaces the internal surface ID with
the public reference, strips URL credentials/query/fragment, and returns
`application/json`. Results use `ttlMs: 0` and `cacheScope: "private"`.

### Action tools

Each explicit binding becomes one MCP tool. Its strict input envelope contains:

- required `revision` observed from the snapshot resource;
- required nested `input` only when the action declares an input schema;
- required `idempotencyKey` only for `keyed` actions;
- no other properties.

The surface ID, element ID, action name, risk, schema, origin, and principal
are never caller-controlled. `tools/call` invokes `performSafe()` with the
internal surface ID captured from current state and the caller's revision.
Stale catalogs therefore fail at the existing core revision boundary.

Successful structured content carries a small projected result with the public
surface reference, previous/current revision, action, target presence, and
action-specific output. Failed calls carry the core's normalized failure code
and message with `isError: true`. Text content is fixed and never interpolates
page text, raw output, policy reasons, or exceptions.

MCP annotations are conservative hints only. They never grant permission or
replace core confirmation.

## Trust boundaries and data classification

The MCP client, tool arguments, client metadata, `_meta`, URI, page text,
snapshot content, and action output are untrusted. Transport authentication is
host-owned. The required authorization callback must map trusted host context
or a trusted closure to access; it must not accept MCP client assertions as an
identity source.

Snapshot state is private by default. Password and sensitive values remain
redacted by core, while the MCP projection additionally removes internal
surface identity and URL credentials/query/fragment. Tool names and
descriptions are trusted developer configuration and are bounded before the
server becomes usable.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | The optional `/mcp` subpath creates a transport-neutral official SDK v2 server without opening a listener or changing root exports. |
| AC-02 | `resources/list` and `resources/read` require authorization and expose only the exact current snapshot URI with private zero-TTL cache hints. |
| AC-03 | Snapshot projection uses the opaque `surfaceRef`, removes URL credentials/query/fragment, preserves core sensitive-value redaction, and emits detached JSON. |
| AC-04 | `tools/list` and `tools/call` require authorization on every request; denial reveals no catalog or raw exception. |
| AC-05 | Only explicit trusted bindings export; duplicate names/targets, invalid metadata, unavailable actions, credential actions, and non-portable schemas fail closed before serving. |
| AC-06 | Every tool has a strict envelope containing only revision, declared nested input, and required keyed idempotency key. Primitive, array, object, and absent action inputs remain representable. |
| AC-07 | Tool execution delegates only to `performSafe()` with a server-bound target and internal surface ID; the client cannot override policy inputs. |
| AC-08 | Stale revision, invalid input, authorization, confirmation, precondition, verification, output-validation, replay, and replay-conflict behavior remain core-owned and normalized. |
| AC-09 | Success returns validated action-specific structured content; failure returns a fixed redacted error result with `isError: true`; neither channel leaks sentinels or stacks. |
| AC-10 | Tool order and schemas are deterministic; metadata and serialized content remain within documented budgets. |
| AC-11 | Cancellation before execution, concurrent stale calls, disposal, retained callbacks, and repeated disposal fail closed without duplicate execution. |
| AC-12 | Official SDK client evidence covers list/read/call through a linked legacy transport and a no-socket modern 2026-07-28 serving path, with tiers labeled separately. |
| AC-13 | MCP and WebMCP calls over the same fixture return equivalent core status, failure codes, revisions, replay semantics, and authoritative final state. |
| AC-14 | The package declares the MCP server as an optional peer, packages only intended MCP output, and a fresh consumer imports root and `/mcp` without framework peers. |
| AC-15 | Typecheck, build, full deterministic gate, frozen 32/6/5 contract, audit, package dry-run, diff check, and isolated consumer checks pass. |
| AC-16 | Independent security and MCP SDK/API compatibility review has no unresolved critical/high finding. |

## Rollback and disable strategy

Do not import the optional subpath, or close/dispose its dedicated server before
closing the host transport. Reverting the P3.1 implementation and package
export removes the adapter without data migration. No persistent store,
network listener, OAuth client, or protocol history is created by this work
item.
