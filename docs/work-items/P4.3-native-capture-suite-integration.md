2026-10-04; implementation continuation under the accepted S2 design/entry and
[collector component checkpoint](../reviews/p4.3-native-collector-component-decision-2026-10-04.md).

## Ownership and layout

Root authors an isolated `CaptureSuite` executable, fixed trusted setup driver,
bounded strict fixture record reader and fixed PowerShell launcher. A separate
implementation agent authors the JS original-byte suite verifier and its
deterministic mutation tests; it must not independently approve its own code.
Actual security/accessibility/package source review follows the combined freeze.
Link unchanged copied foundation and collector component source; do not modify
accepted P4.2 fixture/goldens, public APIs, schemas, exports, manifests or S1.
No native invocation is permitted before final source/binary/verifier approval.

Only a newly launched exact pinned synthetic fixture is in scope. Preserve
anchored admission before modal/popup setup, serial collector calls, exact-thread
window enumeration, explicit safety, owned peer ancestry, bounded private IDs
and all component/foundation limits. No arbitrary app/PID/HWND/thread selector,
Desktop walk, input injection, provider default fallback, persistent service,
installation/elevation, model/provider call or release. Never invoke retained
removed peers. Trusted setup patterns are not S3 adapter execution evidence.

## Execution gate and continuation

Startup/setup/observation stays10 seconds, owned unit worker30 seconds and owned
native worker240 seconds. Bounded file reads use one opened regular handle and
fixed buffers; strict reset/state parsing rejects duplicates, wrong types and
malformed UTF8. The launcher verifies pinned cached SDK/version, unchanged
fixture bytes, worker bytes and final combined source. Native first/repeat run
serially with distinct CreateNew directories; stop at first execution or
verification failure, retain partial artifacts and no automatic retry/budget
widening. Freeze combined source, exact DLLs, case order and verifier first.
Exact `--unit` performs parsing/workload units; exact `--binding` independently
computes the same C#/Node source aggregate using bounded files and filesystem
metadata only, without native application/UIA admission. Native mode requires
the fixed reviewed source/binary freeze before any fixture launch. File/directory
checks handle the legitimate OS8.3 Temp alias, reject reparse points/hard-linked
files and retain sequential/cooperative-filesystem limitations. Setup uses
GW_ENABLEDPOPUP only as an asynchronous startup cue on the owned main; the
complete strict admission frame is mandatory before auxiliary provider reads.
It is not uniqueness/ownership proof, broader enumeration or a default fallback.
For the ComboBox, selecting an item may itself close the WPF popup. Determine
the current closed/popup category using only the owned-main cue, then require
the matching complete frame and explicit ExpandCollapse state before the fixed
collapse. A closed popup is not silently re-admitted as an auxiliary root.

One shared10-second budget spans each complete setup sequence, including all
fresh walks, waits, selected-container proof, admission fences and immediately
pre/post SDK mutation checks. Repeated instances count once in that sequence;
local graph duplicates/cycles still refuse, new instances count cumulatively,
and distinct auxiliary instances are capped64 inside the combined256 before
growth. Setup roots require exact admitted native handle, identity and current
control type (Window for main/modal). Fresh target/current semantic-container
ancestry, explicit safety and typed selection relations precede required pattern
reads; qualification is repeated before mutation. This is trusted fixed setup,
not S3 policy authority or atomic protection against unseen provider ABA.

Worker stdout/stderr retain at most1025/257 original bytes, respectively, with
overflow/fault refusal while reading and strict UTF8 decoding only after bounded
EOF. Pure memory-stream tests cover empty/exact-cap, overflow, malformed UTF8,
incomplete EOF and read faults; they are not OS pipe/worker termination proof.
The launcher kills only its owned worker on collection failure/deadline and
retains partial evidence. Sequential SDK calls and filesystem checks are not
hard COM allocation or administrator containment guarantees.

Source approval uses unique standalone current reviewer/disposition/source/
zero-unresolved metadata, and a distinct two-field fixed-execution decision.
Quoted, fenced, hidden, stale, historical, duplicate or contradictory reserved
fields refuse in both C# and JS. The canonical fields must follow the initial
ASCII plaintext level-one heading (bounded240 characters) and
blank line in fixed order, followed by a blank line; no prior HTML/declaration/
processing-instruction wrapper or hidden context may surround them. Reviews
order reviewer, disposition, source and unresolved count; the execution entry
orders fixed authorization then source. Metadata elsewhere is not authority.
Whole-report Git blob and source/binary pins remain mandatory. These repository records are governance evidence, not a
cryptographic signature proving agent identity or native acceptance.

Primary file-API basis: [CreateFile directory/reparse flags](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew),

and [opened-file metadata](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileinformationbyhandle).
