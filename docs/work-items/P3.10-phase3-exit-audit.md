# P3.10 — Phase 3 Exit Audit and Review Preparation

Status: Planned; prerequisites incomplete (see Phase 3 readiness gaps)

Phase: 3 — Ecosystem, reliability, and evaluation

Required approver: Repository maintainer; security findings require the
security owner

## Problem and user outcome

Individual passing work items do not prove that Phase 3 as a whole meets its
ecosystem, reliability, evaluation, security, compatibility, and packaging
contract. Maintainers need one source-bound audit with honest limitations
before deciding whether Phase 3 closes and P4.1 may begin.

## Dependencies and scope

P3.10 begins only after P3.1 through P3.9 have reviewed implementation and
evidence. It builds the complete acceptance traceability matrix, reruns all
required gates from a clean checkout, prepares the Phase 3 Exit Review, records
independent reviews and non-claims, and presents the native-feasibility
recommendation for maintainer decision.

Current prerequisite gaps are recorded in
[`docs/reviews/phase3-readiness-gaps.md`](../reviews/phase3-readiness-gaps.md).
This preflight does not start P3.10 or authorize its clean-checkout audit.

## Non-goals and prohibited changes

- no runtime feature, schema migration, threshold adjustment, fixture removal,
  or evidence fabrication;
- no automatic approval of Phase 3 or authorization of P4.1;
- no package publication, `0.3` release, tag, deployment, provider spend, or
  native implementation;
- no conversion of missing browser/model/native evidence into a passing claim.

## Trust boundaries and data classification

Historical reports, command output, package artifacts, model results, and
review comments are untrusted evidence inputs until their source commit,
fixture hash, environment, redaction, and completeness are checked. The audit
must not copy secrets into its matrix or attachments.

## Compatibility and rollback

P3.10 changes documentation and reproducible evidence only. Corrections to
completed evidence are append-only and preserve the original record. A failed
gate leaves Phase 3 open; it is not rolled forward by wording changes.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Every P3.1–P3.9 acceptance criterion maps to reviewed design, exact source paths, executable evidence, and a source commit/fixture version. |
| AC-02 | A clean lockfile install, typecheck, build, full deterministic suite, and all required managed-browser suites pass without retry or weakened assertion. |
| AC-03 | Delta, replay, cross-exporter conformance, adversarial, evaluation, and benchmark gates meet their pre-accepted thresholds. |
| AC-04 | MCP and WebMCP pass the same mandatory core conformance suite and Playwright fallback never bypasses policy or confirmation. |
| AC-05 | The Phase 1 contract remains frozen at 32 root runtime exports, 6 declaration files, and 5 schemas unless a separately approved migration supersedes it. |
| AC-06 | Dependency audit, package dry-run, intended-file review, and isolated consumers for root, optional subpaths, and the CLI pass. |
| AC-07 | Artifact-wide scanning shows zero secret leakage and security/adversarial review has no unresolved critical/high finding. |
| AC-08 | Independent API, package, protocol, browser, and security compatibility reviews have explicit dispositions. |
| AC-09 | Golden tasks meet accepted completion, wrong-action, safety, step, and token thresholds with model/provider evidence correctly labeled. |
| AC-10 | Native feasibility is decided from actual web evidence while real-OS, permission, daemon, and language-selection proof remain explicit Phase 4 gaps. |
| AC-11 | Known limitations, unsupported tiers, environment failures, unavailable evidence, and non-claims remain visible in the proposed exit review. |
| AC-12 | The review stops at `Proposed — awaiting maintainer decision`; Phase 4 remains blocked until a separate explicit approval. |

## Planned clean-checkout gate

The final command record will include lockfile installation, typecheck, build,
deterministic and three-engine browser tests, replay/conformance/adversarial/
evaluation/benchmark commands, contract freeze, dependency audit, package
inspection, isolated tarball consumers, CLI smoke tests, documentation links,
and diff checks. Exact commands are frozen by the completed work items rather
than invented during the exit audit.

## Traceability

| Goal | Acceptance criteria | Planned artifact | Planned evidence |

| Complete phase evidence | AC-01–AC-04 | audit matrix and gate record | P3.1–P3.9 evidence links |
| Preserve contract/package/security | AC-05–AC-08 | compatibility and review bundle | clean-checkout/package/review results |
| Honest product/native decision | AC-09–AC-12 | proposed Phase 3 Exit Review | metrics, limitations, approval checklist |

No Phase 3 exit evidence or approval is claimed by this plan.
