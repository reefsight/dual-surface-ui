# P4.3 R1 — frozen-artifact execution, not implicit recompilation

Status: proposed design; no implementation or native entry yet.
Date: 2026-10-09, Asia/Bangkok. Owner: `/root`, under the existing
[maintainer delegation](../reviews/phase4-agent-review-authorization-2026-10-03.md).

## Measured problem and outcome

The [controlled continuation](../evidence/p4.3-controlled-continuation-2026-10-09.md)
passed pure/regression/browser checks but refused the rebuilt DLL. The one
reviewed historical-metadata recipe also failed whole-byte equality/admission
and its restoration assertion. It is consumed; no retry or variant is authorized.
Neither failure is native proof or a diagnosis of the earlier desktop refusal.

The current launcher always compiles before admission. A documentation-only
HEAD change influences informational-version and SourceLink/PDB inputs, even
when the explicitly bound source is unchanged. Its native path can therefore
overwrite an approved frozen artifact before checking it. R1 separates reviewed
compilation/qualification from execution of that exact artifact. It must not
change UIA semantics, OS guards, native budgets or criteria to obtain a pass.

## Genuine build provenance and qualification

After actual independent source review, commit the reviewed source candidate in
a scoped increment. Compile pure mode from that real immutable commit with the
existing pinned SDK 10.0.401, Release/project/import inputs and actual recorded
arguments; preserve genuine SourceLink and current source revision. No historical
metadata override, generated-file rewrite or SourceLink disable is permitted.

The provenance record must bind the real source commit, exact source inventory,
toolchain/project/import inputs, build settings and resulting full DLL hash.
Audit implicit repository/ancestor MSBuild inputs before qualification. If an
unbound input exists, stop and refine this design; do not assume the csproj alone
is the complete build input. New executable build inputs must join both source
inventories and receive actual review before use.

Perform two genuinely fresh compilations serially in that same source context,
using the new fixed pure-mode `dotnet build ... -c Release -t:Rebuild --nologo`
recipe. An incremental no-op or reused cached output is not a repeat build.
Use only the SDK's scoped project rebuild, not broad directory deletion. Compare
the full suite DLL, deps and runtimeconfig bytes from each fresh compilation;
recheck the unchanged fixture DLL/deps/runtimeconfig closure and prove genuine
matching informational/SourceLink revision. These pure builds do
not prove a native scenario. Later reconstruction must use the same admitted
source context/settings, not an arbitrary documentation HEAD. After qualification,
documentation commits may change HEAD but cannot change executing bytes: Native
mode only uses the admitted prebuilt artifact while all bound source remains exact.

Keep build provenance outside the source/binary hash calculation to avoid
commit-self-hashing or source→freeze→binary cycles. The later execution decision
must explicitly bind that immutable provenance record and the exact DLL; the
fixed freeze binds the decision's complete bytes. Do not weaken the parser or
insert an unauthenticated source-equivalence claim to break a hash cycle.

### Closed private build-provenance record

Use exactly six top-level keys: `schemaVersion` (`0.1`), `kind`
(`p4.3-native-suite-r1-build-provenance`), `sourceCommit` (lowercase 40-hex),
`sourceDigest` (SHA-256 shape), `buildInputs` and `builds`. Both C# and JS
must apply identical closed grammar and equality checks, not merely blob binding.
Reject BOM, invalid UTF-8, decoded duplicate keys, unknown/missing fields,
trailing data, depth over 6, tokens over 2048, scalars over 512 UTF-8 bytes and
files over 32 KiB, with the existing fixed-path/regular-file/identity checks.

buildInputs has exactly `sdkVersion` (`10.0.401`), `sdkArchiveDigest` (the accepted
existing archive pin), `project` (literal suite csproj), `configuration`
(`Release`), `arguments` (literal fixed build/Release/Rebuild/nologo argument
sequence), and `files` (the exact ordered thirteen existing application `.cs`
files plus csproj and the fixed global.json, fifteen records total, each closed
path/digest). No additional runtime-selected
input is accepted. Check every listed file against its actual fixed source
bytes. Standard SDK imports are trusted inputs from the previously admitted
cached toolchain, not a claim of hostile-host/toolchain tamper resistance.
Unknown repository/ancestor imports fail the prior qualification audit; this
closed record cannot authenticate an undeclared implicit input.

The fixed-name ancestor audit found only that global.json on 2026-10-09
(terminal chunk `105ef7`, EXIT 0); its exact contents and blob were then read
(chunk `d14af8`, EXIT 0). No Directory.Build.props, Directory.Build.targets or
Directory.Packages.props was present on that checked ancestor chain. This is a
time-bounded qualification prerequisite, not permanent absence proof; repeat
the fixed-name check before the two builds and refuse new undeclared inputs.

builds is exactly two ordered records with keys `lane` (`first`, then `repeat`),
`collectorBinaryDigest`, `informationalRevision`, `sourceLinkRevision` and
`executionFiles`. Each executionFiles is the same exact ordered four closed
path/digest records as the freeze. Both revisions must equal sourceCommit;
both DLL digests must equal the freeze's DLL pin; both companion lists must
equal one another, the freeze and current original files. sourceDigest must
equal the freeze/current source aggregate. Repeated outputs and build inputs
must be identical; retain the first observations before the second fresh build,
and stop on a failure rather than opportunistically rerun.

The genuine source-commit/tree, build occurrences and observed metadata remain
actual qualification evidence for independent reviewers to verify. This JSON
is not self-authenticating proof that a compile occurred or that a claimed
SourceLink revision was genuine. The new fixed freeze admits its whole blob,
closed shape and cross-bindings; later reviewers/entry bind actual terminal
evidence. No new public schema, dependency or caller capability is introduced.

## Risks and rollback

Review stale prebuilt source/artifact mismatch, incomplete implicit build inputs,
PDB/path-dependent bytes, role/profile substitution, hash cycles and misleading
metadata/equivalence claims. Exact admission before all workers and every lane
must fail closed. On any failure retain evidence and withhold the appropriate
entry/acceptance. Roll back only the isolated R1 candidate through normal scoped
version control; never remove historical/user evidence or broaden OS permissions.
No installation/elevation/security-setting change, arbitrary app interaction,
daemon, publication/release/main merge or whole-project Rust migration is in scope.
