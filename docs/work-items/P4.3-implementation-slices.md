Owner: Coordinating implementation agent under the maintainer's

Required human authority remains repository maintainer `Pitchayut586`; actual

## Scope and language boundary

Build a bounded internal Windows UIA reference spike, not a native release or
daemon. Use the already pinned isolated .NET 10.0.401 SDK for the first managed
reference because it can exercise real UIA on the accepted WPF fixture without
a new toolchain installation or runtime dependency. This is a comparative test
candidate, not selection of .NET over Rust. P4.4 must still evaluate Rust and
every viable alternative under ADR 0018 before production-host implementation.
No P4.4 comparative result is produced before its method/candidates are frozen.

Planned boundary: `experiments/windows-uia/managed-reference/`, separated from
`src/`, the accepted P4.2 source files/golden and the npm allowlist. A launcher
may start only this project's synthetic fixture and owned worker processes.
No agent-supplied PID, HWND, selector, executable path, process enumeration,
shell, persistent server, network listener, installation, elevation or input
injection is exposed. The spike must use the unmodified accepted P4.2 fixture.

## Data flow and authority

Trusted local harness admission -> OS user/session/desktop/process/window
observations -> bounded fresh UIA capture -> opaque generation-bound bindings
-> core snapshot/action projection -> policy/confirmation/precondition checks
-> one supported pattern -> fresh capture and separate fixture state -> stable
verified or uncertain core outcome.

Provider metadata, identifiers, tree shape, events, model requests and request
text remain untrusted. Runtime objects/native IDs stay inside the worker.
Fixture state is authoritative only for this synthetic conformance subject,
not a production application API. Redact before storing or serializing: no
sensitive values, raw OS authority, user/profile paths or provider exception
text in reports. Bound every capture/read/frame/operation and kill only owned
workers on deadline; do not bypass the existing fixture deadlines or retry a
failed run into a success artifact.

## Incremental slices

1. Identity/admission slice: trusted owned-process/window admission, current
   OS desktop/session and integrity checks, opaque surface/element generation,
   fresh ancestry/membership resolution, pattern/type-qualified ambiguity
   rejection, and disposal/reset/replacement invalidation.
2. Capture/projection slice: bounded read-only real UIA capture, semantic
   comparison against all accepted P4.2 goldens, live host-owned revisions,
   redaction and extra expanded ComboBox popup-wrapper observations. Public
   snapshots must pass the existing core/protocol admission without new fields.
3. Action slice: the seven reviewed pattern families, schema-valid inputs,
   host policy/confirmation, expected effects and authoritative verification.
   Prove retained callable peers and destroyed-window metadata cannot revive
   old bindings; a denied old binding changes the consequential count zero times.
4. Lifecycle slice: cancellation, serialized concurrency, replay/idempotency,
   local event observation plus reconciliation, dropped/reordered event and
   provider-disconnect injection, unknown post-mutation outcomes and resync.
5. Evidence/review slice: clean real-host runs, complete acceptance matrix,
   failure retention, raw measurement workload for P4.4, full existing gates,
   independent accessibility/security/protocol/race/package review and a
   separately dated delegated acceptance decision.

Each slice gets a scoped reviewed commit and executable evidence. A slice
passing does not mark P4.3 complete. An injected boundary-negative test is
unit/fault-injection evidence, not proof of an actual permission prompt,
secure-desktop transition, alternate OS/session or hostile production provider.
Unavailable real-host proof stays open and must be reported explicitly.

| Goal | P4.3 criteria | Planned source | Required executable evidence |
|---|---|---|---|
| Trusted admission and stale-target refusal | AC-03, AC-06–AC-08, AC-12 | internal host admission/binding/resolver | real owned fixture, detached peer, native window destruction; zero consequential mutation for stale targets |

Agent-model eval is N/A for the first identity slice: no discovery/model choice,
prompt, public catalog or model input path changes. Later capture/action slices
must assess whether the existing deterministic native corpora suffice or a
separately frozen agent-evaluation dataset is needed before claiming model use.

## Rollback and stop conditions

Remove/disable this isolated spike without changing the accepted web SDK,
protocol 0.1, P4.2 fixture/golden or user data. Preserve failed evidence and
source history. Stop a slice on ambiguous authority, disclosure, unverified
mutation, unsupported OS permission requirements, flaky safety assertions,
source/evidence drift or missing real-host proof. No partial implementation or
mock can satisfy the full native/Phase 4 completion gate.
