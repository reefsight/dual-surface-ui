# P1.1 — Core Schema 0.1 and Conformance Fixtures

Status: Implemented; awaiting maintainer review

Phase: 1 — Core contract and DOM reference

Approved start: 2026-09-18

## Objective

Freeze the first versioned agent snapshot contract, generate a distributable
JSON Schema from the TypeScript source, and prove valid, invalid, and secret
leakage fixtures behave deterministically.

## Scope

- Core snapshot and action TypeScript contracts
- JSON Schema source and generated artifact
- Valid and invalid contract fixtures
- Schema/runtime regression tests
- Package contents and dependency audit

## Non-goals

- WebMCP or MCP exporters
- framework adapters
- stale-revision enforcement
- input/output execution validation
- policy engine implementation
- Playwright, extension, model, or native integration

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Every snapshot declares schema version `0.1`. |
| AC-02 | Snapshot requires surface identity, revision, generation time, capabilities, and semantic nodes. |
| AC-03 | Actions can declare risk, schemas, preconditions, effects, confirmation, and idempotency. |
| AC-04 | All valid fixtures pass and all invalid fixtures fail under JSON Schema 2020-12 strict validation. |
| AC-05 | A sensitive state containing a serialized value is rejected. |
| AC-06 | Generated JSON Schema is byte-semantically synchronized with the TypeScript schema source. |
| AC-07 | The exploratory DOM runtime emits the `0.1` snapshot envelope. |
| AC-08 | The npm package dry run includes the generated schema and excludes tests/fixtures. |
| AC-09 | Dependency audit reports no known vulnerabilities. |
