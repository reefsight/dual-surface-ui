# P2.7 — Semantic Drift Checker

Status: Implemented and verified; independent security/API review found no blocker

Phase: 2 — Web standards and framework adoption

Required approver: Repository maintainer

## Goal and outcome

`dual-surface-ui/drift` compares a reviewed semantic manifest with one bounded,
same-epoch observation of the current UI and application evidence. It detects
drift across:

- the current core snapshot and complete action semantics;
- explicitly mapped visible controls, accessibility role/name, and representable state;
- declared WebMCP bindings and exporter-side active registration observations;
- current permission decisions for one principal, origin, and input case; and
- authoritative application-supplied element state.

The checker does not execute an action, handler, confirmation callback,
precondition, effect verifier, or model-supplied code. Permission and state
readers are trusted synchronous observation functions supplied by the host.

## Reviewed manifest lifecycle

Manifest creation and checking are separate trust steps:

1. A trusted build or review job provisions a 32-byte HMAC secret through the
   host secret manager and imports it with `importSemanticDriftIntegrityKey()`.
2. `createSemanticDriftManifest()` captures the reviewed snapshot and explicit
   WebMCP bindings, then produces domain-separated HMAC-SHA-256 digests.
3. The manifest and its fingerprint are reviewed. The fingerprint is pinned
   independently from the manifest; it must not be reassigned from a newly
   generated runtime manifest.
4. Runtime checking imports the same secret, supplies the independently pinned
   fingerprint, and reads current evidence through trusted readers.

`createSemanticDriftIntegrityKey()` creates an ephemeral non-extractable key for
tests or one-process use. It cannot verify a persisted manifest after restart.
Persistent workflows must provision the same secret and import it in each
trusted process. The raw secret and `CryptoKey` must remain outside model, DOM,
snapshot, log, fixture, and report data.

HMAC protects reviewed-manifest authenticity only while the key and pinned
fingerprint remain trusted. Same-origin code that obtains the key reference can
sign new data; this package is not an XSS boundary.

## Observation boundary

`checkSemanticDrift()` requires:

- `readSnapshot()`, reading the current `AgentSurface` rather than a retained copy;
- `readActiveTools()`, reading the current exporter's `toolObservations` on
  every call;
- `readPermission()`, reading a current decision for the supplied context;
- `readApplicationState()`, reading authoritative safe state for each mapped node;
- `readEpoch()`, returning a monotonic safe integer that never repeats; and
- `observationEpoch`, the expected current epoch.

The host must increment the epoch for every relevant surface registration,
DOM/navigation, exporter refresh/dispose, permission, and application-state
mutation. A constant, reused, or ABA-prone token is invalid evidence even if it
has the correct TypeScript shape. Reader callbacks must be synchronous,
side-effect-free, and held in trusted application code.

One invocation covers one principal, origin, and input case. Evaluate multiple
principals or argument cases in separate invocations.

## Privacy and report contract

Accessible names, surface IDs, revisions, URLs, and non-sensitive values are
HMACed with separate domains. Reports contain only the pinned fingerprint,
fixed issue codes, bounded numeric target indexes, coverage counters, and
status. Raw IDs, names, URLs, form values, policy context, and secrets are not
reported.

Credential, token, OTP, password, and sensitive personal values must use the
core sensitive-state projection (`sensitive` and `valuePresent`). They must not
be passed to `digestSemanticValue()`. Stable element/action/tool identifiers are
developer-owned metadata and must not contain user data or secrets.

The checker accepts trusted plain data objects and real platform DOM nodes.
JavaScript cannot inspect arbitrary proxies without invoking proxy traps, so
proxy inputs are unsupported. Errors are normalized to a fixed message.

## Status semantics

- `consistent`: every supported check and required trusted observation matches.
- `drifted`: at least one definitive mismatch or security exposure exists.
- `incomplete`: evidence is missing, transport is unsupported/not observed, a
  resource budget is exceeded, the epoch changes, or a UI state/boundary cannot
  be represented. Definitive drift takes precedence over incomplete evidence.

Open shadow roots and iframe hosts encountered below the selected root produce
`incomplete`; callers may check a same-origin iframe document or open
`ShadowRoot` as its own root. Cross-origin frame contents and closed shadow-root
contents are platform-opaque and require a host-owned separate surface. The
checker does not claim coverage of invisible closed-shadow contents.

## WebMCP evidence boundary

The imperative exporter exposes `toolObservations` on the additive
`InstrumentedWebMcpExportHandle` returned by
`exportAgentSurfaceToWebMcp()`. Each frozen observation records:

- the detached, recursively frozen descriptor used for registration;
- the bound `elementId` and action;
- the snapshot `surfaceId` and revision captured for execution; and
- the registration-batch generation.

The drift checker compares all of that exporter-side evidence with the reviewed
manifest and current snapshot. Descriptor semantics use the same internal
projection as the exporter, covering name, trusted description, normalized
input envelope, and safety annotations. Every observed tool in one active batch
must report the same generation. Refresh replaces the batch with a new
generation, while dispose and failed-batch rollback expose no observations.
Generation proves internal batch coherence only; the manifest does not pin an
expected generation number.

`toolDescriptors` remains a descriptor-only compatibility view, but it is not
sufficient drift evidence because it does not identify the bound target,
surface, revision, or batch generation. Hosts should pass `toolObservations` to
`readActiveTools()`.

These observations prove exporter intent and local lifecycle only. They are not
browser-private registry read-back and do not prove that the browser retained,
exposed, displayed, or invoked a registration. Supported-browser
Inspector/manual invocation remains a separate Phase 2 exit requirement. A
model context that ignores aborts or substitutes registrations cannot be
certified by exporter-side observations alone.

## Resource limits

- 512 snapshot nodes and control bindings;
- 64 actions per node and 1,024 actions total;
- 512 declared or active tools;
- 2,048 scanned DOM elements;
- 256 text nodes and 4,096 text characters per accessible-name traversal;
- 128 composed ancestors;
- 2,000,000 aggregate captured semantic characters; and
- 512 unique report issues.

Exceeding an observation budget produces bounded, truncated, incomplete
evidence. Array length is captured once so changing Proxy length traps cannot
create an unbounded loop.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | `./drift` is additive and preserves the frozen root contract. |
| AC-02 | A reviewed manifest uses a separately pinned fingerprint and domain-separated HMAC key provisioned outside the artifact. |
| AC-03 | The current snapshot is obtained from a trusted reader inside the observation epoch. |
| AC-04 | Complete action semantics cover description, risk, input/output schemas, preconditions, effects, confirmation, and idempotency. |
| AC-05 | DOM mapping checks missing, hidden, out-of-root, unmapped, role, name, safe state, and navigation drift. |
| AC-06 | Declared tools and exporter observations compare descriptor semantics plus bound element/action, surface, revision, and one coherent batch generation. |
| AC-07 | Exporter observations follow refresh/dispose/rollback and are never described as browser registry read-back. |
| AC-08 | Permission readers are bound to one trusted principal/origin/input context and unknown/missing decisions cannot pass. |
| AC-09 | Authoritative state readers cover every mapped node and raw values are rejected. |
| AC-10 | Observation epoch changes, unsupported transport/state, nested boundaries, and budget exhaustion fail incomplete. |
| AC-11 | Reports are deterministic, recursively frozen, bounded, and contain no raw identifiers, names, URLs, or values. |
| AC-12 | Same-origin foreign-realm roots work without ambient-realm `instanceof` checks. |
| AC-13 | Hostile malformed/accessor inputs fail with the fixed error without action execution or DOM mutation. |
| AC-14 | Focused, full-gate, contract, audit, package, and packed-consumer checks pass. |

## Non-goals and limits

- No golden workflow success claim from a drift report alone.
- No handler identity, handler correctness, backend authorization, or effect-verification proof.
- No browser-private WebMCP registry enumeration, retention attestation, or
  proof of what Inspector/model UI exposes.
- No cross-origin frame or closed-shadow inspection.
- No arbitrary backend/business-state schema; application state is the reviewed
  safe projection returned by the host reader.
- No guarantee against a compromised trusted host, leaked HMAC key, dishonest
  reader, non-monotonic epoch, or XSS with access to trusted closures.
- No replacement for framework lifecycle tests, human workflow tests,
  WebMCP Inspector/manual invocation, or production monitoring.

focused drift, DOM, domain, and WebMCP tests

## Evidence

- Focused drift and WebMCP suites pass 50/50 tests; the independent security
  review also ran drift, WebMCP, and DOM conformance together at 65/65.
- TypeScript, core build/schema generation, and Angular compilation pass.
- The serialized full gate passes 21 files and 252 tests, including the
  cross-realm VM runner that exercises foreign-realm plain snapshot data.
- The frozen Phase 1 contract remains 32 root runtime exports, 6 declaration
  files, and 5 schemas.
- `npm audit --json` reports 0 vulnerabilities.
- Package dry-run contains 92 entries (82,969-byte tarball; 430,550 bytes
  unpacked), including the drift runtime/declarations and shared WebMCP
  descriptor runtime/declarations.
- A fresh packed consumer with optional framework peers omitted imports both
  the root and `dual-surface-ui/drift` at runtime and passes strict TypeScript
  checking.
- Independent security and API/package reviews found no actionable blocker;
  the remaining browser-registry and trusted-host limitations are recorded
  above and remain Phase 2 exit evidence rather than P2.7 claims.

## Rollback

Remove the `./drift` package export and `src/drift` entry point, then remove the
additive exporter observation subtype and shared descriptor helper. The frozen
root package and application business logic require no migration.
