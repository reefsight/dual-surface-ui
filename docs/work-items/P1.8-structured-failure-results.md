# P1.8 — Structured Failure Results

Status: Implemented and verified; awaiting maintainer review

Phase: 1 — Core contract and DOM reference

Required approver: Repository maintainer

## Problem and user outcome

Transport adapters cannot safely serialize rejected exceptions from
`perform()`. Consumers need a stable failure result that can be handled without
parsing implementation-specific messages and without exposing secrets or stack
traces.

## Scope

- public failure code, error detail, failure result, and outcome types;
- fixed safe messages for every existing public `AgentError` code;
- `internal_error` normalization for unknown thrown values;
- opt-in `AgentSurface.performSafe()` while preserving `perform()` behavior;
- versioned failure-result JSON Schema, generated artifact, and fixtures;
- deterministic compatibility and secret-leak tests;
- README usage and contract documentation.

## Non-goals and prohibited changes

- no change to the rejection behavior of `perform()`;
- no action lifecycle/audit event transport;
- no logging, correlation store, retry classification, or stack serialization;
- no request echo, raw action input, idempotency key, principal, or origin in a
  failure result;
- no WebMCP, MCP, framework, Playwright, extension, or native code;
- no package publication or version bump.

## Trust boundaries and data classification

Exceptions and thrown values from application handlers are untrusted and may
contain credential or secret data. Failure normalization inspects only whether
the value is a recognized `AgentError` and its stable code. It never copies the
original message, stack, cause, request input, key, principal, or thrown value.
Unknown and malformed errors fail closed as `internal_error`.

## Compatibility

`perform()` remains source- and behavior-compatible. `performSafe()` is an
additive API. The existing success schema remains unchanged; a separate failure
schema and an `AgentActionOutcome` TypeScript union are added.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | `performSafe()` returns the existing success result unchanged when execution succeeds. |
| AC-02 | Every supported `AgentError` becomes a failed result with the same stable code and a fixed non-sensitive message. |
| AC-03 | Unknown exceptions and non-Error thrown values become `internal_error`. |
| AC-04 | Failure results include schema version, authoritative surface ID, latest safely observable revision, and `status: "failed"`. |
| AC-05 | Failure results omit action, target, input, idempotency key, principal, origin, exception message, cause, and stack. |
| AC-06 | Failure normalization cannot throw for hostile unknown values. |
| AC-07 | `perform()` retains its existing rejection behavior. |
| AC-08 | The failure schema accepts valid fixtures, rejects invalid/leaky fixtures, and stays synchronized with generated output. |
| AC-09 | No existing success schema or fixture changes are required. |
| AC-10 | Typecheck, build, tests, audit, ESM import, and package dry-run pass. |

## Design

ADR 0002 defines the public boundary. `normalizeAgentFailure()` owns the fixed
code-to-message mapping. `performSafe()` wraps `perform()` and, on rejection,
refreshes the semantic revision when possible; if observation itself fails, it
uses the runtime's last known revision. The conversion path does not inspect an
unknown error beyond guarded `instanceof` and code lookup.

## Rollback / disable strategy

Revert the single P1.8 commit. Existing `perform()` integrations require no
migration because their behavior is unchanged.
