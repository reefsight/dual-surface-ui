# P4.1 — Language-Neutral Native Protocol

Status: Authorized; design accepted; messages, parser, corpus, and session
verifier implemented and verified; property/cross-language/reviews remain

Phase: 4 — Native surfaces

Required approver: Repository maintainer; protocol/schema changes also require
the technical maintainer; security boundaries require the security owner

## Problem and user outcome

Windows and macOS adapters need one stable way to expose the same safe Dual
Surface semantics to an authenticated local agent. Without a frozen
language-neutral protocol, platform APIs and implementation-language details
could leak into the public contract, adapters could disagree about failures and
authority, and upgrades could replay stale or over-privileged actions.

P4.1 defines and implements the protocol foundation before any OS adapter. A
consumer must be able to validate deterministic fixtures, negotiate
capabilities, read redacted versioned state, and receive stable action/failure
envelopes without acquiring native privileges.

## Scope

- normative protocol 0.1 prose and JSON Schema 2020-12 contracts;
- strict handshake/version/capability negotiation;
- surface catalog, full snapshot, delta, action request/result, cancellation,
  event, and stable protocol-error envelopes;
- opaque session/surface references and explicit request correlation;
- compatibility, reconnect, revision, replay, and size-limit rules;
- canonical golden fixtures covering every message and failure class;
- TypeScript schema validator and implementation-independent verifier;
- round-trip, negative, property/fuzz-seed, secret-leak,
  deterministic-digest, and package-boundary evidence.

## Non-goals and prohibited changes

- no Windows UI Automation or macOS Accessibility calls;
- no daemon, listener, named pipe, Unix socket, network port, service, launch
  agent, installer, signing, updater, or production process;
- no transport authentication implementation or client credential storage;
- no remote access, mobile adapter, mouse/keyboard injection, shell command,
  arbitrary process inspection, raw handle exposure, or memory access;
- no change to the frozen Phase 1 root exports or schemas;
- no package publication, release version, tag, deployment, or native-support
  claim;
- no Rust/.NET/Swift selection or language-superiority claim before the later
  decision gate;
- no C, assembly, or unreviewed unsafe/native boundary.

## Trust boundaries and data classification

The agent, model output, protocol bytes, action input, application content,
accessibility text, client metadata, and reconnect state are untrusted.
Transport-authenticated OS identity, server-minted session/surface references,
process/window binding, policy, confirmation, and authoritative application
state are trusted only inside the future native host.

Protocol fixtures are synthetic. Credentials, password values, tokens,
cookies, private keys, one-time codes, production identifiers, raw OS handles,
and signing material are prohibited from schemas, fixtures, logs, errors, and
digests.

## Public-contract boundary

[ADR 0015](../adr/0015-native-protocol-boundary.md) is controlling. The
[Native Protocol 0.1 specification](../protocol/native-protocol-0.1.md) and
reviewed JSON Schema are normative. Language-specific types are projections
and must reject any input the schemas reject. The protocol is additive under a
native namespace and does not alter the existing npm root contract.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Protocol 0.1 defines every message, state transition, trust assumption, limit, and stable error in normative prose and strict JSON Schema 2020-12. |
| AC-02 | A client completes exact version/capability negotiation before discovery; no compatible version or required capability fails closed without catalog disclosure. |
| AC-03 | Envelopes use bounded opaque request/session/surface references, deterministic tagged kinds, and `additionalProperties: false`; duplicate JSON keys and invalid UTF-8 are rejected before dispatch. |
| AC-04 | Surface discovery and snapshot/delta responses preserve core IDs, revision rules, redaction, classifications, schemas, and resynchronization behavior without raw OS handles or selectors. |
| AC-05 | Action requests bind only to a server-owned session/surface/catalog entry and current revision; callers cannot choose principal, OS user/session, process/window authority, risk, policy, confirmation, preconditions, or expected effects. |
| AC-06 | Action success/failure reuses validated core outcome and stable error semantics; untrusted text, raw exceptions, stacks, platform codes, and accessibility object data never become public messages. |
| AC-07 | Idempotency, replay conflict, cancellation, reconnect, stale revision, process/window replacement, and session invalidation have deterministic fail-closed fixtures. |
| AC-08 | Protocol and audit artifacts retain no credential/secret sentinel; password and sensitive controls expose at most safe presence/classification metadata and are never writable through P4.1. |
| AC-09 | Canonical digest inputs are independent of JSON key order and serializer formatting; ordinary wire parsing does not require canonical source bytes. |
| AC-10 | Every frame, collection, string, schema, snapshot, delta, result, error, and nesting level enforces accepted resource budgets before allocation or dispatch. |
| AC-11 | The TypeScript validator accepts and round-trips every valid golden fixture and rejects every invalid fixture without OS or transport side effects. |
| AC-12 | Fixtures are language-independent: no JavaScript number beyond the exact interoperable integer range, `undefined`, `bigint`, class instance, platform handle, or runtime-specific error representation is permitted. |
| AC-13 | Tests cover every stable failure plus unknown fields/kinds/versions/capabilities, malformed/oversized input, duplicate keys, digest-material mutation, and truncated frames. |
| AC-14 | Compatibility tests prove exact 0.x negotiation, immutable session capabilities, reconnect invalidation, and fail-closed upgrade/downgrade behavior. |
| AC-15 | Property tests and a frozen adversarial corpus cover parser differentials, numeric/string boundaries, allocation abuse, injection text, confused-deputy fields, replay, and secret extraction. |
| AC-16 | Native protocol schemas/specification are included only through an explicit reviewed package boundary; no OS binary or experimental runtime enters the npm tarball. |
| AC-17 | Typecheck, existing deterministic/browser/conformance/security gates, schema generation, dependency audit, package dry-run, and diff checks pass from a clean checkout. |
| AC-18 | Independent protocol, security, interoperability, and package review reports no unresolved critical/high finding before P4.1 completes. |

## Implementation evidence

The first implementation slice provides strict client/server handshake
negotiation. It adds the versioned client-hello, server-hello, and
protocol-error schemas; deterministic capability intersection; fixed
fail-closed errors; bounded opaque identifiers and limits; a TypeScript
validator; and an isolated `dual-surface-ui/native-protocol` package export.

The second slice adds strict surface-list, full-snapshot, and delta
request/response projections. The validator performs descriptor-safe capture,
deep freezing, surface/revision cross-field checks, deterministic catalog and
action ordering, core snapshot/delta schema reuse, secret-state rejection, and
native frame/snapshot/delta/action-count budgets. It does not implement action
execution, cancellation, events, a byte-level JSON parser, transport, an OS
adapter, or a native runtime.

The third slice adds action request/outcome, cancellation, stable
post-negotiation request error, and event projections. It rejects
caller-supplied authority fields, binds outcomes to opaque surfaces, requires
package-owned error text, enforces exact event shapes and safe sequence
integers, and limits action responses to 256 KiB. It still does not execute an
action or implement session state; those responsibilities belong to a future
authenticated native host.

The fourth slice adds the transport-independent UTF-8 JSON frame admission
parser and aggregate message validator. It rejects BOMs, malformed UTF-8,
duplicate keys including Unicode-escaped aliases, comments, trailing or
truncated input, invalid JSON numbers, non-finite results, lone surrogates,
oversized strings/frames, excessive nesting/nodes/properties, unknown message
shapes, non-canonical stable errors, and semantic cross-field violations before
dispatch. It does not select or open a transport.

The fifth slice adds a schema-validated, package-included, language-neutral
fixture corpus with deterministic generation and verification. Its 67 cases
cover every protocol message kind, all 3 handshake errors, all 11
post-negotiation request errors, all 17 core action failures, valid state and
execution envelopes, malformed bytes, duplicate keys, unknown values,
confused-deputy fields, cross-surface substitution, Unicode/parser boundaries,
depth, and frame size. The corpus digest is frozen in the focused test and
recorded under `docs/evidence/`.

The sixth slice adds a fail-closed TypeScript reference session verifier. It
enforces handshake order, negotiated capabilities, session/request/surface and
revision correlation, cancellation targets, contiguous event sequencing,
catalog invalidation, bounded request state, and identical keyed replay. It is
explicitly not an authenticator, authorization engine, transport, or executor.

## Rollback and compatibility

Before protocol 0.1 is accepted, all P4.1 artifacts may be removed without
changing the shipped npm runtime. After freeze, incompatible changes require a
new protocol version, migration fixtures, and an accepted ADR; existing 0.1
fixtures remain immutable evidence. No adapter may claim support for a protocol
version it did not negotiate and validate.
