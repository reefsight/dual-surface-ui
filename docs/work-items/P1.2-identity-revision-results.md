# P1.2 — Stable Identity, Revision Safety, and Action Results

Status: Implemented and verified; awaiting maintainer review

Phase: 1 — Core contract and DOM reference

## Objective

Prevent an agent from acting on an ambiguous or stale surface and return a
versioned result envelope that identifies the exact transition it caused.

## Scope

- documented node-ID lifetime and duplicate-ID rejection;
- surface identity validation;
- semantic revision tracking;
- stale-revision rejection before authorization or execution;
- versioned successful action-result contract and JSON Schema;
- conformance fixtures and regression tests.

## Non-goals

- policy engine or role/origin rules;
- structured failure-result transport;
- domain effect verification;
- MutationObserver streaming or delta snapshots;
- WebMCP, MCP, framework, Playwright, or native adapters.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Registered and declared IDs remain stable for an element lifetime. |
| AC-02 | Duplicate declared IDs fail before a snapshot is returned. |
| AC-03 | A semantic node/state/action change advances the surface revision. |
| AC-04 | Non-semantic DOM decoration changes do not advance the revision. |
| AC-05 | Action requests must match the current surface ID and revision. |
| AC-06 | Stale or wrong-surface requests fail before authorization and execution. |
| AC-07 | Successful actions return a versioned envelope with previous/new revision, action, target, and updated node. |
| AC-08 | Action-request and action-result schemas have valid/invalid fixtures and generated-schema synchronization tests. |
| AC-09 | Password and sensitive values remain absent from snapshots and results. |

## Design decisions

- Revision is a monotonic decimal string local to one `AgentSurface` instance.
- Revision changes when the canonical semantic payload changes; timestamps and
  visual bounds are excluded from the comparison.
- Auto-generated IDs are stable only for the lifetime of the same DOM element.
  Durable application contracts must register an ID or use `data-agent-id`.
- An action request carries `surfaceId` and observed `revision`.
- Failures remain typed exceptions in P1.2; transport error envelopes are
  deferred until the transport contract is designed.
