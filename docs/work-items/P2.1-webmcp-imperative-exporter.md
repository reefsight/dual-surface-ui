# P2.1 — WebMCP Imperative Exporter

Status: Implemented and automated gates verified; supported-browser manual proof pending

Phase: 2 — Web and framework adapters

Required approver: Repository maintainer

## Problem and user outcome

Applications using `dual-surface-ui` already expose a deterministic semantic
surface, but a WebMCP-capable browser cannot discover or invoke that surface.
P2.1 adds an optional browser adapter that registers explicitly approved
surface actions through the experimental WebMCP imperative API while keeping
the Phase 1 core contract authoritative.

## Scope

- additive `dual-surface-ui/webmcp` package subpath;
- feature detection for `document.modelContext.registerTool`;
- explicit developer-owned tool bindings and trusted descriptions;
- one registered WebMCP tool per approved element/action binding;
- object-envelope input schemas that preserve arbitrary core input schemas;
- execution through `AgentSurface.performSafe()` with the captured revision;
- AbortSignal-based registration lifecycle, refresh, rollback, and disposal;
- conservative safety annotations and same-origin-only exposure;
- deterministic fake-context tests plus an isolated package consumer check.
- a dependency-free real-browser support/registration probe for manual evidence.

## Non-goals and prohibited changes

- no automatic export of inferred DOM actions or credential-risk actions;
- no declarative WebMCP, polyfill, framework adapter, MCP server, or fallback
  automation path;
- no `exposedTo` option or cross-origin/iframe delegation;
- no policy, confirmation, validation, idempotency, or verification logic in
  the exporter;
- no mutation of the frozen Phase 1 root exports, declarations, schemas, or
  package version;
- no claim of real-browser support without separate supported-Chrome evidence.

## Trust boundaries and data classification

DOM text, accessible names, page descriptions, action output, and model input
are untrusted. Tool names and descriptions come only from explicit application
configuration and are validated before any registration. Credential-risk
actions are never exported. The adapter closes over surface ID, element ID,
action name, and observed revision, then delegates to `performSafe()` so core
policy, confirmation, preconditions, validation, effect verification, replay
protection, and redacted failures remain authoritative. Tool output is marked
untrusted. Registration omits `exposedTo`, retaining the browser's same-origin
default.

## Compatibility

The root `dual-surface-ui` entry point remains unchanged. The experimental API
is isolated behind an optional subpath and structural local types, with no new
runtime dependency or global DOM augmentation. Unsupported browsers return a
typed unsupported handle and do not mutate the page. The adapter checks an
execution signal before starting; Phase 1 handlers do not yet accept a signal,
so already-started side effects are not represented as cancelled.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Absence of the imperative WebMCP API returns an unsupported handle with no registration or DOM mutation. |
| AC-02 | Only explicit valid bindings register; absent actions, duplicate names/bindings, invalid metadata, and credential-risk actions fail closed before side effects. |
| AC-03 | Each tool uses a valid stable name, trusted description, exact input envelope, and conservative safety annotations. |
| AC-04 | Invocation delegates to `performSafe()` with the bound surface, target, action, revision, input, and optional keyed idempotency key. |
| AC-05 | Invalid input never runs the handler and returns the existing structured redacted core failure. |
| AC-06 | A tool captured against an old revision returns `stale_revision` and does not act on current UI state. |
| AC-07 | Keyed actions require and forward a valid key; replay and conflict behavior remain core-owned. |
| AC-08 | Pre-aborted invocation does not call core; once execution starts the actual core result is returned. |
| AC-09 | Refresh replaces the owned catalog without duplicates, removes unavailable tools, and binds the new revision. |
| AC-10 | Registration or refresh failure rolls back exporter-owned registrations rather than leaving a partial catalog. |
| AC-11 | Dispose is idempotent, unregisters all owned tools, and remount is leak-free. |
| AC-12 | No cross-origin exposure, DOM-derived instructions, or business authorization logic exists in the adapter. |
| AC-13 | The frozen Phase 1 contract, full regression gate, audit, ESM import, and package dry-run remain green. |
| AC-14 | A packed isolated consumer imports `dual-surface-ui/webmcp`; supported-Chrome Inspector/manual evidence remains explicit before browser-complete status. |

## Design

`exportAgentSurfaceToWebMcp()` accepts a structural surface containing only
`snapshot()` and `performSafe()`, an explicit binding list, and an optional
model-context injection used by deterministic tests. Registration is a
transaction: configuration and current actions are validated first, then each
tool is installed with its own abort controller; any failure aborts every tool
installed by that transaction.

All calls use an object envelope. `input` wraps the original action schema so
primitive, array, and object inputs remain representable without reserved-key
collisions. `idempotencyKey` is required only for keyed actions and prohibited
otherwise. The tool closure keeps the observed revision so stale invocations
are rejected by core. `refresh()` serializes lifecycle work, replaces the old
batch atomically as far as the upstream AbortSignal API permits, and `dispose()`
prevents later refreshes.

## Rollback / disable strategy

Do not import or mount the optional subpath, or call `dispose()` on its handle.
Reverting the P2.1 implementation/package-export commit removes the adapter;
there is no persisted data or core migration. Unsupported browsers already
take the no-op path.

- `npm run typecheck`: passed.
- `npm run build`: passed; additive `dist/webmcp` declarations and ESM output
  generated without changing the five frozen schemas.
- Focused imperative-exporter suite: 10/10 tests passed, covering unsupported
  feature detection, explicit export, exact schema/annotations, redacted invalid
  input, stale revision, keyed replay/conflict, pre-abort, refresh, dispose,
  remount, partial rollback, refresh/dispose race, and unsafe configuration.

  exports, 6 declaration hashes, and 5 schema hashes.
- `npm audit --json`: 0 known vulnerabilities across 108 dependencies.
- `npm pack --dry-run --json`: passed with 56 intended package entries,
  41,017-byte tarball, and 216,805-byte unpacked package.
- Fresh temporary consumer installed the tarball and imported both the root
  `createAgentSurface` function and `dual-surface-ui/webmcp`
  `exportAgentSurfaceToWebMcp` function.
- Real Chrome opened `examples/webmcp-imperative/manual.html`; the page reported
  `UNSUPPORTED` because `document.modelContext.registerTool` was unavailable.
  This proves graceful fallback in the current browser, not WebMCP registration
  or Inspector/manual invocation. Supported-Chrome browser proof remains open
  and P2.1 must not be presented as browser-complete until it is captured.
- `git diff --check`: passed.
