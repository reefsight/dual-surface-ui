# P1.6 — Handler Output Contract and Runtime Validation

Status: Implemented and verified; awaiting maintainer review

Phase: 1 — Core contract and DOM reference

Required approver: Repository maintainer

## Problem and user outcome

Actions can advertise an `outputSchema`, but handlers cannot return a typed
result and the runtime neither validates nor safely serializes output. P1.6
makes declared outputs enforceable and ensures undeclared handler values never
enter the agent-facing result by default.

## Scope

- allow custom handlers to return an unknown value;
- normalize declared output into a JSON-safe value;
- validate normalized output against the action's JSON Schema;
- return validated output in the successful action-result envelope;
- omit handler output entirely when no `outputSchema` is declared;
- continue authoritative effect verification even when output validation fails;
- add stable `invalid_output` failures without echoing output data;
- update the action-result schema, fixtures, README, and deterministic tests.

## Non-goals and prohibited changes

- no secret-classification DSL or automatic field-level output redaction;
- no handler exception envelope or structured transport failure result;
- no output streaming, binary output, files, or non-JSON class instances;
- no idempotency/replay cache or audit-event transport;
- no WebMCP, MCP, framework, Playwright, extension, or native code;
- no package publication or version bump.

## Trust boundaries and data classification

Handler output is trusted application data but is not automatically safe for a
model. It crosses the agent boundary only when the action explicitly declares
an `outputSchema`, normalization succeeds, and validation passes. Applications
must not include credential or secret fields in that declared contract.
Undeclared outputs are discarded without serialization. Validation failures
never include the raw output, schema internals, or stack traces.

## Compatibility

Existing void handlers and actions without `outputSchema` retain their result
shape. A handler may return a value without changing the public result until an
output schema is declared. Actions already advertising `outputSchema` now fail
closed if their handler output is missing, non-JSON, or schema-invalid.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | A handler may return a synchronous or asynchronous value. |
| AC-02 | Valid declared output is normalized, validated, and included in the success result. |
| AC-03 | Invalid or missing required output returns `invalid_output`, never success. |
| AC-04 | Malformed output schemas fail closed with `invalid_output`. |
| AC-05 | Cyclic, BigInt, function-only, and otherwise non-JSON outputs fail closed. |
| AC-06 | Handler output is omitted and not serialized when no output schema is declared. |
| AC-07 | Effect verification still runs when output validation fails. |
| AC-08 | Output-validation errors do not contain raw output or secret values. |
| AC-09 | The versioned action-result schema and fixtures accept optional JSON output. |
| AC-10 | Existing input validation, policy, confirmation, preconditions, and effect verification remain unchanged. |
| AC-11 | Typecheck, build, tests, audit, ESM import, and package dry-run pass. |

## Design

- `AgentJsonValue` represents the serializable result boundary.
- Handler output is captured immediately after execution.
- When `outputSchema` exists, the runtime serializes and parses the value to
  produce a detached JSON value, then validates that normalized value.
- Output-validation failure is retained while effect verification runs; if the
  effect verifies, the stable output failure is returned. Effect failure takes
  precedence because the authoritative state transition was not confirmed.
- When no output schema exists, the returned handler value is ignored without
  calling `JSON.stringify` or inspecting its fields.

## Rollback / disable strategy

Revert the single P1.6 commit. No persisted state or migration is added.
Applications can omit `outputSchema` during pre-release adoption to retain a
void public result while still using internal handler return values.
