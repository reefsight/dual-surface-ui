# P2.3 — React Lifecycle Adapter

Status: Implemented and verified; awaiting maintainer review

Phase: 2 — Web and framework adapters

Required approver: Repository maintainer

## Outcome and scope

React applications can provide an existing `AgentSurface` through context and
bind explicitly defined semantics to committed DOM elements with one ref hook.
The adapter owns lifecycle only: it does not create policy, infer metadata,
execute actions, subscribe to snapshots, or auto-export WebMCP tools.

The additive `dual-surface-ui/react` subpath exports:

- `AgentSurfaceProvider` for an application-created surface;
- `useAgentSurface()` for the exact provider value;
- `useAgentElement(definition)` for commit-phase registration and cleanup.

## Trust and compatibility boundaries

Definitions are explicit developer input. The adapter never reads children,
labels, ARIA text, values, errors, or credentials. Action execution remains in
core, preserving policy, confirmation, validation, stale-state, replay, and
verification behavior. Registration occurs only in a React ref commit, never
during render, so abandoned concurrent/SSR renders cause no mutation.

React is an optional peer (`^18.2.0 || ^19.0.0`) and a development dependency,
not a runtime dependency of root/core/WebMCP consumers. P2.3 intentionally does
not add an async WebMCP hook: a safe StrictMode serializer for exporter setup
and early cleanup requires its own reviewed work item.

## Acceptance criteria

| ID | Requirement |
|---|---|
| AC-01 | Provider exposes the exact supplied surface; missing provider fails deterministically. |
| AC-02 | The ref hook registers only a committed DOM element with the exact explicit definition. |
| AC-03 | Human markup and React event behavior remain unchanged. |
| AC-04 | Unmount removes the owned registration and `data-agent-id`; remount leaves one current registration. |
| AC-05 | StrictMode ref replay leaks no registration and creates no duplicate live definition. |
| AC-06 | Definition, element, or provider-surface change cleans the old registration before the new one. |
| AC-07 | Duplicate IDs and core errors fail closed and are not swallowed. |
| AC-08 | Core remains the sole execution/security authority. |
| AC-09 | Server rendering performs no registration or global document access. |
| AC-10 | Root contract, WebMCP adapters, full gate, audit, package, and isolated consumers remain green. |

## Rollback

Remove the optional React import or revert the P2.3 commit. React unmount calls
the exact disposer returned by core. There is no persisted state or migration.
