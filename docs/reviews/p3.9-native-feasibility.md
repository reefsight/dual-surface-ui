## Structural measurement interpretation

The structural run at source commit `a7a7eb6a7e3504c15a20d639a007b928571a9030`
covered all 12 frozen tasks with 25 retained samples per available baseline.
Median serialized size was 567 bytes for the Dual Surface projection, 4,930
bytes for the representative full-page DOM, and 7,382 bytes for the
representative accessibility tree. These numbers describe only serialized
structural representations. They do not prove the 60% token target,
end-to-end latency, model completion, step reduction, or vision performance.

The Phase 1 negative result remains controlling context: its small semantic
snapshot estimate was 6.8% larger than the corresponding full DOM. The new
structural result does not erase that failure and has no exact tokenizer data.

## Model benchmark disposition

The later canonical four-baseline run at commit `d63b439` used exact provider
usage and scored all 144 calls with zero environment errors. It passed with
97.92% completion, 0% wrong actions, zero unauthorized consequential actions,
zero secret leaks, 50% median step improvement, and 88.12% median token
improvement. This supplies the model/token evidence that the structural run
alone could not claim; it does not erase the Phase 1 negative result or prove
native OS behavior.

## Recommendation

Proceed with conditions to P4.1 language-neutral protocol design after the
Phase 3 exit gate is approved. P4.1 may specify messages, capability
negotiation, error semantics, versioning, and trust boundaries. It must not
authorize a native adapter, daemon, platform claim, or implementation language.
Rust, .NET, Swift, and other choices remain Phase 4 measurement decisions.
