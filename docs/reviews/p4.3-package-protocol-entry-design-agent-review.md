## Compatibility conclusions

| Boundary | Reviewed conclusion and references |
|---|---|
| Public package | P4.3 stays an internal local library/harness. Native binaries, daemon/service/install/update/signing work and publication are excluded; the frozen web SDK and protocol 0.1 cannot change. This is consistent with the existing `package.json:8` exports and `package.json:69` allowlist. See `P4.3-windows-uia-adapter.md:17`, `:40`, `:48` and `:159`. |
| Authority and identity | Fresh current-container/tree membership, pattern/type qualification, host-owned generation and OS window liveness remain internal resolution requirements. Provider AutomationId wrappers are not automatically public duplicates, while multiple qualified semantic targets fail closed. Nothing requires PID/HWND/runtime-ID/COM/selector fields in public messages. See `0017-windows-uia-adapter-trust-boundary.md:20`, `:22` and `P4.3-windows-uia-adapter.md:61`, `:89`, `:109`. |
| Golden comparison versus live state | P4.2 IDs/timestamps/reset revisions are comparison data. The adapter independently mints live surface/revision bindings and matches semantic nodes/state/actions, avoiding fixed fixture identity as public authority. Expanded ComboBox wrappers require separate real capture rather than claiming they are present in post-collapse P4.2 trees. See `P4.3-windows-uia-adapter.md:99`, `:107`, `:110`. |
| Uncertain effects and cancellation | Existing `AgentActionOutcome` has only `succeeded`/`failed`; `verification_failed` explicitly means effects could not be verified. The new design uses that existing failure and refresh/resynchronization, prevents known-no-effect/false-cancellation claims, and prohibits a new wire status/field. Explicit uncertain-effect evidence must remain bounded internal development evidence, not an extra field or caller/provider-controlled public error text. See `P4.3-windows-uia-adapter.md:93`, `src/types.ts:99`, `src/types.ts:112`, `src/errors.ts:45` and `src/native-protocol/types.ts:149`. |
| Events and races | A local counter cannot prove provider notification delivery. Authoritative reconciliation, explicit resynchronization and dropped/reordered/racing event tests fit the existing `event`, `resync_required`, closed-session and revision rules. Internal provider diagnostics do not add event kinds or raw provider data to protocol 0.1. See `0017-windows-uia-adapter-trust-boundary.md:24`, `P4.3-windows-uia-adapter.md:94`, `:96`, `:115`, `src/native-protocol/types.ts:186` and `:204`. |
| Replay and stale bindings | Process/window/control removal, replacement, reset and reconnect invalidate internal generation-bound authority. Still-callable retained peers and readable stale metadata cannot revive an old target. The zero-consequential-mutation negatives and frozen idempotency/replay rule are compatible with current session verification. See `P4.3-windows-uia-adapter.md:117`, `:119` and `src/native-protocol/session.ts:188`. |
| Language decision | The entry design permits bounded comparative spikes; P4.4 retains the measured final language decision and Rust preference. No package export or schema is coupled to WPF, CLR, Rust, COM layout or serializer defaults. See `0017-windows-uia-adapter-trust-boundary.md:26`, `:28` and `P4.3-windows-uia-adapter.md:121`, `:161`. |

The added verification scenarios are concrete: detached callable peers,
destroyed-window metadata, equally qualified targets, container swaps, expanded
ComboBox popup wrappers, membership refresh, dropped/reordered events and
uncertain mutation. They are future runtime acceptance requirements, not
evidence that the proposed adapter already implements or passes them.
