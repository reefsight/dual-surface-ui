## Initial finding R1-INT-01

Severity: Medium. The genuine build-qualification method is incomplete.

The design requires two serial builds in the same committed source context to
prove reproducible bytes. The existing pure launcher invokes ordinary
`dotnet build`; without changed inputs, a second invocation can reuse existing
compiled output. Matching hashes then establish incremental artifact reuse,
not two independently produced artifacts. That would overstate the new build
provenance and does not resolve the measured reproducibility problem.

Before accepting the design, specify two genuinely fresh controlled
compilations from the same real committed source and reviewed inputs, using
an explicit bounded method such as a reviewed forced Rebuild. Do not delete
broad paths or rewrite source/generated metadata. Preserve both actual build
terminals and compare the suite DLL, `.deps.json` and `.runtimeconfig.json`
from each generation, together with their genuine informational/SourceLink
revision. The accepted fixture remains immutable and separately admitted.
Cached-output reuse must not be labeled a successful independent rebuild.

The current Native path should remain build-free; this finding concerns only
the pre-execution qualification method. It does not authorize an additional
historical-metadata recipe, different SDK, runtime change or native probe.
