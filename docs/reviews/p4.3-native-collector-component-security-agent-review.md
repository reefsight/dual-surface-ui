## Findings chronology and source resolution

### P43-NCC-SEC-001 — Medium: competing owned-window subjects ignored

Initial `OwnedWindowTopology.Admit` filtered additional visible/enabled windows
by `Owner == anchoredMain` before determining ambiguity. Static counterexamples
were a main plus a visible/enabled ownerless peer under `None`, and a main plus
the expected direct-owned popup plus an ownerless/wrong-owner visible peer under
`Modal`/`Popup`. Those frames could pass the old filter. This violated the
reviewed refusal of competing/unprovable subjects; no native exploit was run.

`resolved_source`: `OwnedWindowTopology.cs:28` now counts all additional
visible/enabled candidates, then requires exactly the expected direct-owner
relationship. `Program.cs:47` through the adjacent two vectors preserve the
ownerless/wrong-owner counterexamples with exact `Unavailable` expectations.
The complete bounded candidate frame remains in the post-capture comparison,
including hidden/disabled candidates. I independently reread the fix.

### P43-NCC-SEC-002 — Medium: UIA subtree ancestry could bypass a native boundary

Before the boundary fix, `Visit` checked process and current UIA parent but did
not establish the native root of a nonzero HWND encountered beneath the admitted
Control View root. A hidden/disabled unadmitted top-level peer, or a same-process
different-thread peer presented beneath main, could reach Name/pattern reads;
eventual Window-subject refusal was too late, and a structural wrapper might not
trigger it. This was an adversarial static ordering case, not observed provider
behavior or an actual foreign-app read.

`resolved_source`: `ReadOnlyCollector.cs:95` and `:111` check the typed explicit
native-handle boundary before `Observe`/content. Root acquisition, selected-peer
resolution, auxiliary ancestry and current-member fences also apply that check.
`OwnedWindowsAdmission.cs:64` requires nonzero handles to be live, owned by the
anchored PID/thread, on the ordinary admitted desktop, with `GA_ROOT` equal to
the already admitted main or auxiliary, then repeats native identity/root
checks. `OwnedWindowTopology.cs:44` rejects another/zero native root and wrong
PID/thread. Logical zero handles cannot establish a new root; unsupported or
malformed properties fail rather than default to zero. Main/modal roots still
require exact UIA/native correspondence and Window type. No broader enumeration
or first-match fallback was added.

`Program.cs:118` contains seven pure boundary vectors: two positive and five
negative, not seven executed OS negatives. The negatives cover hidden unadmitted
root, wrong thread/PID, other root and zero native root. I reviewed their code,
not an actual provider fixture or independent unit run.

### P43-NCC-SEC-003 — Low: private runtime-ID bound drift

The preliminary collector allowed 64 runtime-ID parts, while accepted S1 used 32.
This was bounded but an unreviewed widening, not a secret disclosure.

`resolved_source`: `ReadOnlyCollector.cs:15` retains 32 and `:373` refuses
null/empty/over-limit arrays. `Program.cs:113` checks 32 accepted and 33/null/empty
refused, with exact `ResourceExceeded` for the negatives.

### P43-NCC-SEC-004 — Low: disposal refused publication only after native reads

At the earlier `eabf...` target, `Dispose` retired only `SemanticSession`;
subsequent serial `Capture` could perform admitted OS/UIA/host-fence reads before
the session refused publication. No retired snapshot could succeed, but zero
post-disposal provider-call claims were not supported. I notified root before
the final checkpoint.

`resolved_source`: final `ReadOnlyCollector.cs:26` checks a private disposed flag
before constructing the budget, admission or host-fence calls. `:56` sets it and
permanently disposes the linked session. `Program.cs:125` adds the three pure
checks: exact `Unavailable` with deliberately absent admission, untouched
throwing host-fence callback, and idempotent disposal. I reread the complete
three-file delta and independently verified its new aggregate. This is serial
source behavior, not disposal-race/COM evidence.

Other roles/root also addressed ownership-first identity reads, selected
ancestry/accounting before pattern acquisition, private/nonchosen SelectionItem
fences and strict summary admission. I independently inspected the final code;
I do not claim those other reviews or executions as my own.

### P43-NCC-SEC-005 — Medium: hidden runtime-ID reads during fresh comparisons

Discovery belongs to the actual accessibility/interoperability reviewer, not
this security review's initial findings. The earlier Same helper passed freshly
returned parent/current-selection operands to Automation.Compare without first
gating both operands. Microsoft's comparison implementation fetches both runtime
IDs; the collector's explicit Instance PID/length checks therefore did not cover
that hidden read path. [Microsoft WPF comparison implementation](https://raw.githubusercontent.com/dotnet/wpf/main/src/Microsoft.DotNet.Wpf/src/UIAutomation/UIAutomationClient/MS/Internal/Automation/Misc.cs).
I independently checked the implementation basis and re-reviewed the fix;
there was no executed OS/provider exploit.

`resolved_source`: final `ReadOnlyCollector.cs:346` handles null before comparing
and uses CompareAfterProof. Both nonnull operands pass current PID and native
boundary checks before bounded salted Instance comparison; no Automation.Compare
call remains in the collector. I inspected all Same callers: current parent
proof, exact auxiliary-root pruning, selected container, existing auxiliary
ancestry, root termination/refresh, nonchosen container and current selected-peer
fences. A null parent produces false and the caller refuses; a malformed/foreign
operand or failed boundary never reaches the comparison callback. The explicit
identity getters still retain ownership, 32-parts/text and the shared deadline.
`Program.cs:134` adds 22 pure proof/comparison assertions, including both operand
positions, null/NotSupported/wrong-type/foreign PID, failed boundary proofs and
equal/unequal safe comparisons. These are callbacks/static facts, not OS evidence.

## Security assessment of the final component

- Admission is private and anchored to an owned Process/birth/token/main HWND
  and its native thread. `MainWindowHandle` is read once before auxiliary setup,
  not refreshed into a modal. Pre/post admission checks exact user/session/
  integrity, no elevation/UIAccess, active local session, WinSta0 and ordinary
  Default/input desktop. Scalar token buffers are exactly 4 bytes; SID queries
  are bounded at 4096 bytes with pointer/header/revision/subauthority/length checks before
  copying. Private identities are not serialized. Borrowed thread-desktop
  handles are not closed; acquired input/token buffers/handles are released.
- The 64-callback cap precedes filtering; callback faults/overflow latch refusal
  rather than unwind through native code. Two complete native frames compare
  all candidates and main/auxiliary identity facts before returning a snapshot.
  There is no process/thread sweep, desktop UIA walk, caller selector, injected
  input or native action method. Source flags attest only internally admitted
  roots; neither type/ID nor a synthetic DTO grants OS authority.
- Explicit basic Boolean observations precede Name/content/pattern reads.
  Exact NotSupported is unknown; null/wrong types refuse. Unknown basics remain
  private structure, with no content/pattern reads or public semantics. Known
  sensitive subjects never read password Name/value/patterns. Only the fixed
  seven typed semantic families are inspected; no false/writable defaults are
  manufactured. Value/range/read-only states remain separately observed.
- Selected peers require owned native boundary, safe basic flags, bounded
  current ancestry and auxiliary accounting before their pattern/state/content
  acquisition, typed SelectionItem and exact expected container/selected=true.
  All copied SelectionItems, including private/nonchosen ones, have fresh
  nullable selected-state/container/pattern fences. The linked pure projector
  rejects graph defects, ambiguity and private reciprocal contradictions.
- One outer 10-second budget spans native frames, trees, selected relations,
  copied native text/nodes and current/reset fences; deterministic foundation
  validation does not reset it. Combined 256 nodes, roots 2, depth 16, children 64,
  auxiliary 64 within 256, text 131072 and runtime parts 32 remain bounded. Opaque
  binding retirement/256 cumulative issuance, semantic fingerprints, monotonic
  revision and capped encoding remain the separately reviewed foundation.
  Publication is returned only after all outer fences; failure invalidates maps.
- Public snapshots contain only `snapshots` and empty actions. Private descriptive
  catalogs/inverse correlations are not an endpoint or model capability. Runtime
  IDs, handles, paths, wrappers, exceptions and native geometry are not public
  fields. Selection values are opaque references, not native IDs; inert observed
  names/value strings never enter shell commands or executable HTML.
- `Program.Main` accepts only `--unit`; it never constructs admission or performs
  native collection. The disposed-lifecycle unit calls Capture only to prove its
  first guard before admission/fence/provider access. Unit errors are closed
  literals. The owned unit launcher
  withholds raw streams, rejects malformed UTF-8, retains BOM for refusal and
  passes only the separate exact, duplicate-key-refusing, bounded summary parser.
  Its PowerShell bridge is reencoded unit metadata, not original native artifact
  provenance. Binding scripts only read/hash the explicitly listed source paths.

The accepted Window clarification is preserved: current native/typed UIA Window
root proof is mandatory, while seven semantic families do not assert raw P4.2
WindowPattern parity. No golden node/schema/criterion is dropped and the
collector/projector has no golden/oracle state input. Native comparison is not
implemented by this component; future independent all-golden verification must
not infer parity from source or unit-summary success.

## Limits, accepted lower risks and unchanged stop conditions

Approval permits only checkpointing this isolated development component and
continuing the authorized implementation. It does **not** authorize a native
run, certify the future setup/launcher/verifier, accept S2 or waive any gate.

The component assumes a trusted internal serial caller: Capture/Invalidate/
Dispose must not race, and main admission must precede auxiliary setup. Synthetic
facts and injected callbacks are not real native desktop/token/window/provider
negatives. Zero native handles remain logical provider membership backed by the
bounded current ancestry, not independent HWND proof. Sequential OS/UIA reads
cannot prove atomicity, unseen handle/runtime-ID ABA or hostile-provider honesty.
Managed caps do not contain allocation or latency inside one provider getter;
SDK/provider element acquisition may also prefetch/cache private identity;
explicit comparison gates are not a guarantee of no internal framework reads.
The future fixed 240-second worker boundary remains mandatory. The unit launcher
post-buffers streams before length refusal; this acknowledged trusted fixed-unit
process limit is not a general streaming/provider allocation guarantee. Source
normalization/marker checks are not a signed binary or protection against a
same-user filesystem adversary. These are accepted component-scope limits, not
claims of production-adapter security.

Still required before native S2 execution/acceptance: complete fixed trusted 22
setup cases, both modal snapshots and extra expanded/collapse ComboBox membership
evidence; owned fixture/worker/output/reset admission; exact source/binary/case/
budget/verifier freeze and actual reviews; independent original-byte comparison
and unchanged core/protocol admission; live revision/reset/replacement/restart
assertions; serial first/repeat with first-failure stop and retained failures;
fresh required final-source browser/conformance/package/security gates; actual
artifact reviews and a separate dated S2 decision. No native result exists for
