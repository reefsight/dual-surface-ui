## Substantive source assessment

- `IdentityCatalog.cs:110-158` defensively copies bounded observations/patterns,
  rejects malformed graphs, requires exactly one Window root, proves every node
  reaches it without cycles/missing parents, and enforces node/depth/child/text
  budgets. `:161-187` derives ancestry from that graph, qualifies correlation,
  type and required pattern before ambiguity rejection, and never chooses the
  first matching provider ID. A duplicate container correlation refuses rather
  than inventing container authority.
- `IdentityCatalog.cs:55-107,195-214` serializes validation, refuses malformed or
  unknown receipts locally, fresh-captures known receipts, invalidates private
  generations on observed changes/errors and refuses recovery of old bindings.
  `:189-193` restricts read-only refusal to Value/RangeValue, so an otherwise
  eligible read-only ComboBox can still qualify for ExpandCollapse. No executable
  peer or callback escapes a receipt/decision.
- `NativeObservation.cs:19-78` starts at the owned admitted window, counts every
  ControlView node including wrappers without usable correlation, checks current
  parent/process membership, rejects repeated runtime identity, bounds traversal,
  then rechecks OS window/root/reset fences. It does not read Name/help/value
  content. Sensitive nodes do not receive pattern reads. `:82-90` is visibly a
  trusted fixture-setup helper, not receipt authority or an executor.
- `WindowsAdmission.cs:17-85` combines owned-process lifetime with user/session,
  matching non-elevated/non-UIAccess integrity, active-session, WinSta0/Default
  input-desktop and native window/thread ownership checks. Borrowed desktop
  handles are not closed; opened handles/buffers are released. No PID/HWND
  selector or alternate-user enumeration path is exposed.
- `Program.cs:127-138` now requires `!IsWindow` for the formerly owned native
  window before labelling the destroyed-window metadata probe. Detached patterns
  and destroyed metadata are read but never invoked; unchanged-state assertions
  therefore prove only this decision-only path. Reset fencing uses append-only
  record ordinals (`:189-197`), not the resettable acknowledgement sequence.
- Unit definitions now cover target absence/reparenting/ambiguity and recovery,
  graph/budget negatives and exact boundaries, defensive pattern copying,
  collection faults, deadline/error recovery and serialized validation. They are
  useful algorithm evidence, not actual OS desktop transitions or UIA capture.
