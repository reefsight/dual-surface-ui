## Closed record and admission checks

The twelve required keys are `schemaVersion`, `kind`, `sourceDigest`, `collectorBinaryDigest`, `fixtureBinaryDigest`, `case`, `stage`, `site`, `classification`, `code`, `cleanupCode`, `recordedAt`. There are no optional/additional keys. The private kind is `p4.3-native-capture-suite-failure`, version `0.1`; all three lowercase 71-character SHA-256 pins must equal separately admitted D1 authority, not merely values asserted by the record itself.

All data is flat strings or explicitly allowed nulls. The exact stage/site/case mapping distinguishes output/startup/setup/capture/publication/report/cleanup; output requires bootstrap and null site, while post-SetCase execution retains its current fixed case. Only already-required suite property observations can produce not-supported/malformed-property; they cannot describe an unseen collector getter. Those categories require the designated property site and InvalidObservation. The four unchanged CaptureCode values remain guarded refusal codes; explicit SDK faults, TimeoutException and unexpected errors have the separately stated static classification/code mappings. Error messages, HRESULT, stacks, Data, inner exceptions, provider type names and native identities cannot enter the record.

Limits are 4096 original UTF-8 bytes, depth 2, 32 JSON tokens and decoded string length 128. A valid flat twelve-key object occupies 26 tokens, within the cap. Strict UTF-8, no BOM, no trailing JSON, decoded duplicate-key/escaped-alias rejection and malformed UTF-16 rejection are mandatory. Valid JSON escaping cannot widen the closed enum/key/value rules. Timestamp is exact 24-character UTC millisecond syntax with real calendar/time validation. These are private diagnostics limits, not changes to core/protocol schemas or transport budgets.

`failure.json` is the only diagnostic file, at an already admitted fresh fixed first/repeat directory. The native worker alone writes it, CreateNew, bounded before publication. Capability is granted only after canonical fixed-path/ancestor/empty-directory admission; a raw CLI argument or early entry refusal cannot become a write target. The new read-only CLI accepts only `--failure-directory`, separately admits the actual fixed D1 freeze, and opens only the regular single-link diagnostic through bounded cap-plus-one/current-identity/ancestor checks. It does not enumerate or decode partial provider/capture/recorder files, launch an app, write output, use C0 fallback or accept caller-selected approvals.

A partial or complete suite report may remain after report/stdout refusal. Failure-only inspection retains it without decoding or treating it as success. Its output carries admitted closed metadata, the original-byte digest and `nativeAccepted:false`, never a successful case count. Conversely the unchanged success verifier's exact artifact topology rejects a failure file. Presence or admissibility of either diagnostic metadata or a leftover report cannot override a failed worker or establish native acceptance.

## Primary failure, cleanup and authority

Static scoped operation/site context is restored on normal return; the innermost unhandled refusal latches an immutable closed tuple before unwinding. Outer catches/cleanup/publication cannot replace the primary. This is first synchronously observed unhandled refusal, not a claim about the earliest asynchronous stream fault or an underlying cause.

An already-required getter is read once; unchanged post-read deadline checks precede sentinel/type classification. NotSupported followed by ResourceExceeded therefore remains guard-refused/ResourceExceeded, with a deterministic ordering test required. No diagnostic provider read, default substitution or post-refusal mutation is introduced. Expected provider-rejection probes wrap the complete already-existing rejection operation, so an intentionally caught probe exception is not latched as terminal failure. Unchanged collector errors retain only caller capture-call context, not fabricated property localization.

Cleanup is limited to already-required owned resources. A per-owned-process stopAttempted flag is latched before the first stop, including restart/final stop; later report/stdout refusal cannot kill/dispose again. Existing required collector/process/stream/handle closure actions are each attempted once with independent catches so one fault does not skip remaining closure. A later new owned process gets a new flag, not a global process lookup. Secondary cleanup code cannot mask the primary; primary cleanup failure has null secondary code. A blocked call, hard worker kill, early admission, pipe fault or diagnostic publication refusal may leave no admitted record. Absence does not justify a fallback, retry, wider deadline or invented location, and a diagnostic file does not prove cleanup completed.
