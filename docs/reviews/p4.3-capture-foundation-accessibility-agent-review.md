## Accessibility and interoperability checks

I inspected all trusted subject definitions against the accepted fixture mapping:
reviewed roles/types, containing subjects, the seven required semantic pattern
families, sensitive host label and disabled/read-only behavior. Names and values
are copied input, not manifest/golden expected values. Matching correlation alone
does not confer authority. Same-type/container ambiguity is rejected before
safety/pattern filtering; different-type Combo Text wrappers remain private.
See `FixtureSubjects.cs:14` and `SemanticProjection.cs:79`.

Any unknown password/enabled/offscreen flag is structural-only. Pre-read Name,
patterns, values or rectangle classification on such an input is refused;
sensitive content is likewise refused rather than read then redacted. The
callback content gate has explicit getter-not-called cases for the full Boolean/
unknown matrix. Missing optional state is distinct from false; invalid enum
values/nonfinite or out-of-bounds ranges refuse; indeterminate/partial/leaf
states do not invent actionable Boolean semantics. Value and Range read-only
unknowns cannot grant write descriptors. See `CopiedObservation.cs:117`,
`SemanticProjection.cs:29`, `SemanticProjection.cs:168` and `UnitCases.cs:39`.

Selection uses current copied instance/container relationships, not labels or
fixture state. Duplicate labels retain separate opaque IDs. A collapsed selected
peer can have a private reference without being a visible node. An explicitly
admitted popup's selected peer may be projected through its current main
container; every graph root still needs its own proof. The expanded/collapsed
vector at `UnitCases.cs:97` is synthetic and does not establish actual popup
ancestry, ownership or current provider behavior. Radio subjects are not forced
to invent a Selection container absent from the reviewed fixture mapping.

The model-facing snapshot has `snapshots` capability and empty actions; the
separate comparable form contains descriptive metadata only. Neither exposes
an executor. References are random and scoped to generation/instance/container;
removal, replacement, container change, failure, disposal and exhaustion cannot
resurrect retired IDs. Revisions are locally monotonic; generated time and oracle
counters do not create a semantic change. See `SemanticProjection.cs:232`.

I inspected strict byte parsing, duplicate-key/UTF-8/UTF-16/depth/length refusal,
exact core/native admission, and the private bijective inverse comparator.
Only the reviewed selection/combo/tabs value slots translate an opaque item
reference; arbitrary edit/range values, names and missing/extra semantic fields
are not masked. The JS suite's all22 main and two modal shapes are explicitly
synthetic verifier inputs, not C# collector outputs. Actual C# serialization is
checked separately by the cross-runtime unit wrapper. Source references:
`p4.3-capture-contracts.mjs:1`, `p4.3-capture-contracts.mjs:108`,
`p4.3-capture-contracts.mjs:136`, `verify-p4.3-capture-unit.mjs`, and
`test/p4.3-capture.test.ts`.

## Window clarification

Approved as a bounded design clarification: Window/window semantic roots remain
required, but the foundation does not add an eighth semantic family or claim raw
WindowPattern presence. The future collector must supply an OS-admitted, current,
typed/lifetime-proved Window root; a synthetic `AdmittedWindowRoot` Boolean is
not that proof. Auxiliary graph-root proof is separate and cannot substitute for
the published Window root. Windows have no Window action descriptor. See the
increment's Window section, `FixtureSubjects.cs:8`, `SemanticProjection.cs:70`
and `UnitCases.cs:293`. This preserves the seven-family semantic boundary while
making the deliberate difference from P4.2 raw manifest qualification explicit.
It is not approval to drop native authorization or silently claim raw-pattern
parity. Record this clarification separately before native use.
