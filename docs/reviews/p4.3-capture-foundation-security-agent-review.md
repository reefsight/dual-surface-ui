### P43-CF-SEC-001 — Medium: auxiliary graph root admission could be omitted

The earlier projector required `AdmittedWindowRoot` only on PublishedRoot.
A second declared root could be an unadmitted Pane while a known-safe `combo-a`
beneath it supplied `SelectionContainer = private-combo`, Selected true and
the current combo's SelectedInstance. `Container()` followed that relation,
and the selected-peer qualification could accept the peer despite its actual
ancestry ending at the unadmitted second root. The existing expanded-popup
positive vector itself used an unadmitted Pane root.

Final resolution: CopiedObservation.cs lines 45–57 distinguishes trusted
`AdmittedGraphRoot` from the more specific Window-root proof. Window admission
implies graph admission. SemanticProjection.cs lines 56–76 requires every
parentless declared root to carry graph proof, rejects graph proof on a child,
and retains stricter published/semantic Window requirements. Every parent
chain is cycle/depth checked and must end at a declared admitted graph root.
UnitCases.cs line 287 adds the exact unadmitted auxiliary selected-peer negative;
the popup positive now explicitly supplies its synthetic proof.
Status: `resolved_source`, not evidence that a real popup was OS-admitted.

### P43-CF-SEC-002 — Medium: raw owned-worker stderr was echoed

The earlier unit launcher bounded stderr length but then emitted
`Write-Output $err.TrimEnd()`. The C# Program catch emits fixed categories, but
an SDK/CLR startup or crash stream need not have that format. Even at <=256
characters, it could disclose a profile/path or exception. Merely owning the
worker does not make its entire stderr a safe public diagnostic.

Final resolution: run-p4.3-capture-unit.ps1 lines 39–45 refuses nonempty stderr
with the closed literal `Capture unit worker reported stderr; raw diagnostic
withheld.` It never prints raw stdout/stderr; stdout is passed only to the
strict separate Node validator, whose success output is a compact summary and
whose catch emits a fixed refusal. test/p4.3-capture.test.ts line 129 adds a
source regression assertion. Status: `resolved_source`; source assertion is
not live CLR crash/fault-injection evidence.

### P43-CF-SEC-003 — Medium: contradictory single-selection relations accepted

Starting from BaseNodes, mark `selection-b` Selected true while the container
still explicitly selects `private-selection-a`. Earlier code proved selected a
but did not reject b also being selected. A known-empty selection could likewise
coexist with a related selected item, including a private collapsed combo peer.
The first fix counted only qualified/publication candidates. Adding a known-safe
private ListItem with empty correlation, explicit Selected true and
`SelectionContainer = private-selection` bypassed that filter while the public
container still selected a. Filtering must not hide contradictory observations.

Final resolution: SemanticProjection.cs lines 101–110 counts all copied
related nodes, not just qualified subjects. It rejects more than one explicit
selected peer even when container selection is unknown, and rejects a known
empty/different selected instance contradicted by any explicit selected peer.
The subsequent selected-target validation still requires the qualified exact
peer, explicit Selected true, expected container and SelectionItem family.
UnitCases includes visible/collapsed/unknown-container negatives plus exact
private-peer counterexamples at lines 252 and 257. The known-empty positive
explicitly clears the old item's selected state. Private nodes are not made
public to implement the check. Status: `resolved_source` in `79d57772...`.
