## Security assessment

The new private format has exactly fifteen required flat fields. Its root
start/end tokens and fifteen key/value pairs consume exactly32 tokens. Both
parsers retain the4096 original-byte, depth2 and128 decoded UTF-16-unit string
limits, with well-formed string validation. They refuse BOM, malformed UTF-8,
raw or escaped duplicate decoded keys, unknown/missing fields, nested values,
arrays, booleans, numbers, trailing content, invalid timestamps and stale pins.
The fixed reader hashes original bytes rather than a reserialized surrogate.

All28 context labels are closed source constants. A window-handle site requires
a recognized context at setup in a fixed non-bootstrap case, with both
admission fields null; other sites require explicit null context. Container
contexts are restricted to selection/tab/combo, and cross-root contexts to
combo/modal-cancel/modal-confirm. The existing forty constructor-admission
pairs retain their three permitted locations. CTX1 and legacy kinds reject
each other, and legacy encoders refuse rather than strip non-null context.
The shared literal corpus supplies the same72 original-byte vectors to both
languages, with32 acceptance vectors and40 refusal vectors.

Context is active only around the single required window-handle read. The
sequence remains pre-deadline check, one getter, post-deadline check, then type
classification. Post-read deadline refusal still precedes unsupported-value
classification. The innermost catch latches the first tuple before transient
site/context restoration. Earlier process-ID failures and later operations do
not inherit the label. Outer catches, admission callbacks, cleanup and
publication cannot replace that tuple. Cleanup clears transient context while
retaining its independent first cleanup code and once-only closure/publication
behavior. No exception message, provider value, equality method or ToString
result is retained.

The actual setup wiring matches all28 design edges, including separate Same
operands and explicit target/container routes. Guard still checks the process
before the window boundary. The property getter keeps `ignoreDefaultValue:
true`; NotSupported is refused, not converted to zero. Typed zero remains a
typed property result, while the unchanged ownership/root-proof checks retain
their original authority. No new OS/UIA probe, tree walk, getter, mutation,
ownership relaxation, retry, input fallback or deadline extension was found.

The adjacent project has explicit compile inputs, distinct assembly/output and
no reference to the old assembly. Node admission checks the original R1 packet
before candidate admission; the managed candidate independently reconstructs
the fixed baseline source and checks its pinned packet/files. The launcher
checks preservation before/after candidate work, never rebuilds the original
project, and admits the legacy DLL only in its fixed pure-unit mode. Missing
actual candidate freeze/reports/provenance/entry refuse before fixture launch.
Failure reading stays in the owned fixed path grammar with bounded original
bytes, link/hardlink/identity checks and directory rechecks; it reads no partial
capture, recorder or report and returns only explicit negative evidence.

A valid context label is not an authorship signature or ownership proof. A
writer able to forge an entire admissible record can substitute a valid label;
actual producer provenance and the separately reviewed original bytes remain
necessary. Source/report pins are governance evidence, not cryptographic proof
of reviewer identity.

the actual production callsites or unchanged native-call inventory. A wrong
source enum or reversed Same operand could therefore escape those assertions.

`test/p4.3-native-suite-ctx1.test.ts`. I reread the actual patch. It binds every

ordered native/tree/pattern/mutation/check and typed property-read inventories
with R1, adjusting only the extracted window-handle helper. Planted wrong-label,
reversed-operand and extra-getter mutations demonstrate sensitivity. Root's
post-remediation test run passed. The Medium finding is resolved; no additional
actionable findings remain in this review.
