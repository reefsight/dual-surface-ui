## Findings

### AI-P42-AI-01 — Medium — selection and ComboBox state are incompletely compared

Status at initial review: open. Provisionally resolved in the working-tree
remediation independently verified below; final source-bound approval pending.
Roles: accessibility, interoperability.

At `scripts/p4.2-fixture-contracts.mjs:149`–`152`, the oracle checks the ComboBox
selected ID and list/tab item flags, but does not compare `selection` container
`values.selection` with `state.selection`, or `tabs` container selection with
`state.tab`. The normalizer publishes those unchecked container fields as
`state.value` at line `117`. Thus an initial raw list can say that
`selection-b` is selected while fixture state and the two item flags say
`selection-a`, and still become an admitted core snapshot. The same defect
exists for tabs. The ComboBox `values.expanded` is also unchecked even though
the Capture source explicitly collapses it before taking the tree
(`fixtures/native/windows-app/Capture/Program.cs:112`–`114`). Changing its
initial raw expanded state to `true` is admitted.

Reproduction was performed on independent in-memory clones of the first real
golden capture, passed to `verifyCapture` with the real manifest and validators:

```js
capture.cases[0].raw.nodes.find(n => n.id === "selection").values.selection = ["selection-b"];
// Independently: tabs.values.selection = ["tab-b"];
// Independently: combo.values.expanded = true;
```

All three variants were admitted. Expected assertions: list and tab container
selection equals authoritative state and agrees with item flags; the captured
post-action ComboBox is collapsed. The actual frozen golden is consistent in
all 44 main cases; this finding concerns false admission rather than a current
golden discrepancy.

### AI-P42-AI-02 — Medium — an expanded case can omit its descendant

Status at initial review: open. Provisionally resolved in the working-tree
remediation independently verified below; final source-bound approval pending.
Role: accessibility.

`scripts/p4.2-fixture-contracts.mjs:159` is automatically true whenever the
fixture says the expander is expanded. The required-control list at lines
`140`–`142` does not include `expanded-child`. Deleting that node from the
`expand` case therefore passes the oracle and produces a normalized expanded
control with no expected descendant, despite the deterministic fixture creating
that child at `fixtures/native/windows-app/Fixture/Program.cs:117` and the
scenario promising its exposure when expanded.

```js
const expanded = capture.cases.find(c => c.id === "expand");
expanded.raw.nodes = expanded.raw.nodes.filter(n => n.id !== "expanded-child");
```

This variant was admitted. Expected assertion: when `after.expanded` is true,
the child exists, is visible/nonempty, belongs to `expand`, and maps to its
qualified Invoke action. When collapsed, it must be absent or excluded. The
stored runs correctly have the child only in the expanded case.

### AI-P42-AI-03 — Medium — raw tree identity is insufficiently cross-checked

Status at initial review: open. Provisionally resolved in the working-tree
remediation independently verified below; final source-bound approval pending.
Roles: accessibility, interoperability.

At `scripts/p4.2-fixture-contracts.mjs:171`–`176`, modal evidence must share the
main process reference and differ from the main window reference. The oracle
does not require the two separately opened dialogs to have different window
references. It also does not bind a raw tree's `windowRef` to its root node's
`instanceRef`. The same missing root/window relation affects main trees. These
references are both generated from the same UIA identity in Capture
(`fixtures/native/windows-app/Capture/Program.cs:325`–`338`), so disagreement
is inconsistent evidence rather than an allowed provider-lifetime variation.

```js
capture.cases.find(c => c.id === "modal-confirm").modalRaw.windowRef =
  capture.cases.find(c => c.id === "modal-cancel").modalRaw.windowRef;
```

This variant was admitted, including its now-inconsistent modal root identity.
Expected assertions: each main/modal raw root is the correct fixture-owned
window, its `instanceRef` equals the tree's `windowRef`, and the two modal
lifecycles are distinct. All 48 stored main/modal trees satisfy the root binding,
and the recorded cancel/confirm dialog references differ in each run.
