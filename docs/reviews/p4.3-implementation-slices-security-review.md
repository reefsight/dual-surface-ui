| Trusted admission and authority | Approved. Only trusted harness admission can launch the known synthetic fixture and owned workers. Caller requests cannot supply an executable, native identifier, arbitrary selector or process-enumeration authority. OS desktop/session/integrity observations and host-owned generation must be checked before exposing a binding, and before mutation; UIA metadata is correlation data. |
| Current target resolution | Approved. Fresh ancestry/membership, required pattern/type qualification, ambiguity rejection, reset/replacement/disposal invalidation and expanded-popup observations address the retained-provider/wrapper behavior actually measured in P4.2. A callable old peer or readable destroyed-window metadata does not reestablish authority. |
| Budgets and serialization | Approved as a design requirement. Capture/read/frame/operation bounds, redaction before persistence/public serialization, existing schema admission and an owned-worker kill deadline are explicit. The implementation must freeze concrete maximums and enforce them before controllable allocation/traversal/frame serialization, with overflow and malformed-input evidence. Provider/API-internal allocations need an explicit worker resource bound or an honestly stated limitation; a schema maximum, timeout or post-serialization size check alone cannot prove bounded memory. |
| Pattern execution and stale bindings | Approved. Policy, confirmation, schema-valid input and effects are explicit preconditions for one reviewed pattern operation. The mandatory stale-peer negative must prove both no stale pattern invocation and zero consequential fixture-state mutation, using the authoritative state and asynchronous completion discipline rather than an immediate count read alone. |

Serialized concurrency, replay/idempotency, dropped/reordered/disconnect injection, authoritative reconciliation and resynchronization are in scope. ## Entry and evidence limits

The full P4.2 acceptance gate and separately dated ADR 0017/P4.3 entry decision
are still required before runtime work. This design approval does not fill a
canonical approval record, accept an ADR, or waive remaining P4.2 regression,
package, review or delegated-maintainer gates.

The identity/admission slice must prove rejection before mutation and record
host-owned invalidation on fixture reset, control/window replacement and worker
disposal. It should preserve the measured P4.2 retained-callable peer and
destroyed-window metadata cases as real negatives. Tests that merely replace a
runtime ID, throw an injected exception, or observe two controls with distinct
IDs but duplicate labels cannot prove the actual stale-peer and equally qualified
target ambiguity obligations.

OS identity/integrity/desktop checks need actual safe OS observations for the
owned fixture plus explicit boundaries on what was not exercised. Unsupported
alternate-session, secure-desktop or permission evidence must remain open for
the relevant acceptance criterion. The fixture remains synthetic; its state
files do not establish a production application's postcondition API.

The P4.2 launch-timeout history and successful serial-run condition remain
relevant. A worker deadline makes failure bounded; it does not establish reliable
startup under load. Each failed run remains a failed artifact. No automatic
retry, widened deadline, or fixed sleep can substitute for actual current
window identity and fixture-state readiness. Startup/concurrency measurements
for P4.4 must retain failures and their tested host/load conditions without
inventing a cause.

No native support, production daemon, remote-access, multi-OS/DPI, hostile
provider, secure-desktop or final bridge-language acceptance follows from this
report. If the brief's reviewed blob changes materially, its security design
disposition must be revisited before relying on it for an entry decision.
