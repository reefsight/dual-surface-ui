## R1 SEC 01 Build provenance admission

Severity: Medium. Status: unresolved in the initial design.

The ten-key freeze requires a fixed buildProvenance path/blob but does not
define the provenance file's own closed record, parsing/file bounds or semantic
equalities with the freeze. An implementation could hash arbitrary JSON or
accept inconsistent source/DLL/companion declarations while claiming to have
admitted provenance. A pinned blob does not replace the promised exact C#/JS
record grammar or authentic qualification observations.

Resolve this in the design before implementation. A small private record is
sufficient; no public schema or generalized build service is needed. Recommended
top-level fields are exactly `schemaVersion`, `kind`, `sourceCommit`,
`sourceDigest`, `buildInputs` and `builds`. Use fixed version/kind literals,
lowercase 40-hex commit and the existing lowercase prefixed SHA-256 grammar.
The reviewed schema should define:

- `buildInputs`: the fixed SDK version and accepted archive digest, literal
  project, Release configuration, exact argument list and a bounded reviewed
  input-file allowlist of fixed path/digest pairs. Inputs are observations,
  never executable commands or caller-selected paths. Unexpected implicit
  imports must refuse and trigger reviewed refinement.
- `builds`: exactly two ordered result records, each containing the whole DLL
  digest, informational revision, SourceLink revision and the same four ordered
  execution-file records. Require both result sets to match, both revisions to
  equal sourceCommit, sourceDigest to equal the freeze's aggregate, and every
  DLL/companion digest to equal the corresponding frozen execution binding.

Suggested conservative bounds are 32 KiB original bytes, depth 6, at most
2048 tokens, at most 512 UTF-8 bytes per scalar string and at most 64
pre-reviewed input records. Reject BOM, invalid UTF-8, duplicate or unknown
fields, malformed scalars and trailing data before accepting the record. Use
the same fixed-file identity, alias and bounded-read controls as other admitted
records. The exact adopted shape and limits require actual C#/JS negative tests.

Admission proves the frozen record's grammar and bindings, not the historical
truth of a producer assertion. The separate entry and authentic qualification
reviews must bind the actual committed source, build inputs and two observed
build results. Do not treat self-declared JSON revisions as source authority,
claim version strings alone prove equality, or create source/record/hash cycles.

companions, but the statement prohibiting extra companions leaves known optional
runtime configuration behavior unspecified. An adjacent `.runtimeconfig.dev.json`
can affect probing without changing any of those four admitted files. The design

apphost; keep the launcher restricted to the admitted DLL through the fixed
runtime. The accepted SDK/runtime baseline remains part of the execution
qualification, rather than a claim that four companion hashes freeze Windows.
