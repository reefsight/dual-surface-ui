The earlier exported `readCapturePublication` checked `stat(path).size` and then called `readFile(path)`. File growth/replacement could therefore allocate more than the 1 MiB report limit before parsing rejected the result. This was a source-inspected resource-bound counterexample; I did not execute an exploit or claim a current native exposure. The helper was not used by the unit CLI.

The new unit source covers exact regular-file bytes, oversized files and directories (`test/p4.3-capture.test.ts:135`).
