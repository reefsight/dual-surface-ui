### P43-S2-D-SEC-001 — Medium: selected value privacy/representation gap

Initial lines 64–65 forbid public correlation, but lines 92–100 and 183–188
did not define how a live selected relationship becomes state.value while
matching golden strings containing AutomationId correlations. Copying the
selected peer's ID would preserve golden equality but violate the privacy
boundary; selecting by duplicate labels or assuming the selected peer is a
published node would not resolve it. Collapsed ComboBox selected peers may
be absent from the public flat tree.

Resolved in the actual final design: public state.value is a stable opaque
selected-item reference, equal to its public node ID if visible. A nonpublic
selected peer requires proven bounded current relation/safety and consumes
the shared 256 binding cap. Only reviewed Selection/Combo/Tab comparison values
may be translated via an exact bijective inverse table; textbox/range/arbitrary
strings and missing/colliding mappings cannot be rewritten. No new core field
or public native selector is introduced. Required tests cover duplicate labels,
private collapsed peers, reference retirement and arbitrary selector-looking
textbox strings. Status: `resolved_design`; source/runtime proof still required.

### P43-S2-D-SEC-002 — Medium: auxiliary discovery/safety/budget scope gap

Initial lines 42–58, 92–100 and 145–154 required final admission and a bounded
relation walk but left modal acquisition/uniqueness and auxiliary getter/counter
scope underspecified. An implementation could first search desktop UIA, accept
the first enabled popup, read a selected peer's text before its safety flags,
or give each auxiliary walk a new budget, while interpreting the final checks
as sufficient. An owner relation or same PID alone cannot make those choices
safe or bounded.

Resolved in the actual final design: native enumeration is limited to the
already-admitted main window's exact owned UI thread after PID/desktop checks,
64 nonchild candidates, two complete passes, no Process.Threads/EnumWindows/
desktop traversal/caller input. At most one additional live visible/enabled
direct-owner-main subject is allowed; missing/competing/unprovable subjects,
incomplete callbacks and different-thread popups fail instead of widening scope.
Pre/post set/identity/thread/owner/desktop/process fences are mandatory.

Every selected peer gets explicit safety before any text/pattern state, typed
SelectionItem, explicit IsSelected true and SelectionContainer matching the
admitted container, bounded current ancestry and a post-read relation check.
Unknown basic safety remains private structure with no Name/content/pattern
reads. Main/modal/popup/auxiliary work shares one ten-second stopwatch, 256
unique nodes, text/binding counters; auxiliary nodes do not add an unbounded
second map. Status: `resolved_design`, not proven native behavior.

### P43-S2-D-SEC-003 — Medium: stable reference/revision ambiguity

Initial lines 117–124 required random references and stable revisions for
identical captures without expressly requiring reference reuse or specifying
the canonical fingerprint. Fresh IDs or generatedAt in that fingerprint could
churn identities/revisions; excluding newly minted IDs without a stable map
could instead claim the same revision while changing node/selection references.

Resolved in the actual final design: exact per-generation surface and private
instance/container maps are reused, including auxiliary selections. Removal,
replacement and container swaps retire references; rediscovery cannot revive
them. Reset/window/process replacement rotates the generation/map. The
fingerprint includes copied semantic subjects/metadata, current private
relations and generation, while excluding timestamps, fixture/oracle counters,
provider events and case IDs. Time-only stability and state/container/generation
changes require independent tests. Status: `resolved_design`; unobserved ABA
and atomic executor safety remain explicitly unproven.

### P43-S2-D-SEC-004 — Medium: publication/comparator contract insufficiently frozen

Initial lines 81–85 and 183–188 demanded complete comparison but did not freeze
semantic-subject publication or the exact inverse/normalization contract and
negative-verifier assertions. A runtime filter built from the expected golden
could omit a real duplicate/missing subject; a broad value/envelope normalizer
could make a wrong state or malformed actual snapshot appear equal. The
existing P4.2 normalizer uses static fixture IDs/revisions and is not a drop-in
live S2 authority or independent expected-output generator.

Resolved in the actual final design: trusted reviewed subject definitions
qualify correlation/type/pattern/container within admitted membership;
unreviewed chrome remains private and same-type/container unknown ambiguity
refuses capture. The golden/oracle node list cannot become a runtime filter.
Each qualified subject has one inverse entry. Exact envelope/reference/
capability/selected-value translations are listed; roles, names, arbitrary
values, focus and unmatched fields are not masked. Verifier mutations must
reject missing/extra/duplicate subjects, bad roles/names/states/descriptors/
schemas, inverse collisions, missing relations, unexpected focus and extra
fields. Actual observations and independent expected frozen golden/fixture
state remain separate inputs. Status: `resolved_design`; implementation and
adversarial verifier execution are not supplied by this review.

## Final assessment and non-waived implementation obligations

The final proposal preserves the accepted security boundary: only the pinned
owned fixture, strict OS admission before content, copied bounded DTOs, no
provider object/exception/handle serialization, password and unknown-content
getter suppression, inert observed injection text, no generic input fallback,
and no S1/P4.2/public schema/package modification. Modal/popups and non-tree
selections are explicitly additional admitted/bounded roots/relations rather
than untrusted UIA ancestry becoming OS authority.

Read-only model-facing snapshots must always have actions[] and only the
snapshots capability. Private descriptor-comparison output is distinct and
cannot be exposed as an executable catalog or model-facing action capability.
Source review must prove no mutating pattern method is reachable from capture/
projection and that literal trusted setup stays separate. Known disabled or
read-only state may need bounded nonmutating pattern-state reads to match the
disabled-toggle/read-only goldens; copying S1's action-eligibility predicate
or inventing default false is not a substitute for actual observed state.
Unknown basic flags still prohibit those reads. Title/other content must use
the same admitted, explicitly safe bounded observation policy.

GetSelection can return a default empty collection; explicit typed property
support and current relationship proof are therefore needed. SelectionProperty
and SelectionContainerProperty identify provider relationships, not trusted
OS membership. These distinctions are supported by
[Microsoft GetSelection](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionpattern.selectionpatterninformation.getselection?view=windowsdesktop-10.0),
[SelectionProperty](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionpattern.selectionproperty?view=windowsdesktop-10.0)
and [SelectionContainerProperty](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.selectionitempattern.selectioncontainerproperty?view=windowsdesktop-10.0).
Explicit current reads distinguish unsupported/default values and may change
after retrieval; pre/post checks do not make them atomic.
[Microsoft current-property API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.automation.automationelement.getcurrentpropertyvalue?view=windowsdesktop-10.0).

GW_ENABLEDPOPUP returns a first enabled owned popup or the original window;
it is not a uniqueness proof. The revised bounded owned-thread enumeration
addresses that design gap, but callback budget/error state and OS ownership
must be implemented and tested without searching unrelated windows.
[Microsoft GetWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow),
[EnumThreadWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumthreadwindows).

Freeze exact source, binaries, setup cases/order, relation/admission budgets
and independent verifier before actual execution. All 22 pinned goldens and
the extra expanded ComboBox evidence, both output representations, native/core
admission, retained bytes/redaction scans, verifier-negative cases, current
full regressions and actual serial first/repeat must pass without retries,
oracle values feeding the projector or broad normalization. Only subsequent
source/evidence reviews and a separate dated decision can accept S2.

## Limits and cutoff

No S2 source, native capture, selection relation, modal uniqueness, redaction
getter suppression, resource-limit execution or schema/golden parity has been
proved here. The reviewed design can fail on actual provider relationships;
retain that failure and request a reviewed refinement, not a default or wider
traversal. Provider/COM internal allocations and blocking getters are not
bounded by managed DTO/schema caps; outer worker limits are not a memory or
atomic snapshot guarantee. Same-user filesystem/SDK trust, unseen ABA,
production hostile providers, real permission/session/secure-desktop negatives,
executor/postcondition/races/events/replay/cancellation remain later obligations.

At final design read cutoff no separate S1 or S2 entry decision existed. Root
has separately reported fresh S1 full/browser/conformance/audit terminal results;
their admission belongs to the separate S1 evidence addendum, not this design
approval. Model-facing input changes in S2, so deterministic schema/golden
proof is not model understanding or task-success proof; the proposed separate
evaluation method/dataset and actual authorized provider calls remain required
before any such claim. Rust/P4.4 comparison, other platforms, public native
support and full P4.3/Phase 4 completion are not accepted.
