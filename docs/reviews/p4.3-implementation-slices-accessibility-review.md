already pinned isolated SDK (`P4.3-implementation-slices.md:13`–`:19`). It does
not select .NET as the production bridge, install a new toolchain, create a
release/daemon, or modify the web SDK/protocol. Its placement outside `src/`, the
accepted fixture/golden and npm allowlist is explicit at `:21`–`:26`. Owned
fixture/worker launch is a trusted harness capability; caller-selected PID,
HWND, selector, executable, arbitrary enumeration, shell, injection, listener,

## Measured provider behavior and proof distinctions

The stale-binding requirement is substantive. P4.2 measured a removed WPF
button peer that remained callable and incremented synthetic state; it also
measured readable metadata after native window destruction. A cached peer's
successful property/pattern calls cannot authorize mutation. The identity slice
requires fresh membership/ancestry and invalidation, and the action slice
requires denied old bindings to produce zero consequential mutation. This is
consistent with ADR 0017 decision 6 and P4.3 AC-06/AC-12, including OS window
liveness independently of UIA metadata.

The consequential-count assertion at `:58` directly measures the retained
Invoke button's synthetic effect. During implementation, it must remain a
scenario-specific assertion: stale Value/Toggle/Selection/RangeValue operations
need their relevant authoritative state verified unchanged as well. The wider
table requirement of zero consequential mutation at `:77` and P4.3 AC-12
provide that obligation; unchanged count alone is not a proxy for every pattern.
No defect is asserted in the plan on that basis, and no such implementation was
inspected or approved here.

The capture slice explicitly supplies the missing expanded ComboBox wrapper
observations. P4.2's post-collapse golden contains no raw `combo-a`/`combo-b`
node. Its successful pattern-qualified selection operation does not prove
expanded popup-tree mapping. The new slice must distinguish wrapper ID reuse
from multiple qualified semantic candidates, bind items to the fresh current
container, refresh after expand/collapse, and reject remaining ambiguity under
the parent P4.3 lifecycle rules. The brief's type/pattern qualification and
extra capture requirement preserve those distinctions.

Fixture state is authoritative only for this synthetic subject (`:38`–`:39`).
Fresh UIA state, generation-bound resolution and trusted policy remain necessary;
reading the fixture's record is not a production application control channel.
Static fixture IDs, revision resets and fixed golden timestamps are comparison
data, while adapter identities/revisions are host-owned under the parent work
item. Public snapshots must retain the existing core/protocol shape (`:54`),
and uncertain post-mutation evidence must use existing verification/refresh
semantics without implying that no mutation happened.

The lifecycle slice and `:68`–`:71` correctly label injected provider disconnect,
event loss, alternate authority and permission negatives as fault-injection/unit
evidence. They do not claim an observed secure-desktop/permission transition,
alternate OS/session or hostile production provider. Real-host proof that cannot
be obtained remains open; a successful synthetic negative cannot close it.

The brief also preserves the P4.2 startup limitation. Its unchanged deadline and
failure-retention instructions at `:41`–`:43` prevent a failed launch from being
retried into an apparent success. Reference evidence must record serial/concurrent
workload conditions and failed samples. The two admitted serial P4.2 captures
do not establish concurrent-load reliability, universal startup latency or the
cause of the earlier launch failures. Later performance comparisons remain
subject to P4.4's separately frozen workload/outlier method.

## Checks and limits of this disposition

This reviewer read the complete brief, current ADR 0017/P4.3, ADR 0018/P4.4 and
delegation; inspected exact line references; mapped the slices to the 18 parent
criteria; compared them with the independently reviewed P4.2 stale-provider,
ComboBox, event and launch observations; and obtained the document blob hashes
above. No `.env` or unrelated user data was read. No adapter source, fixture,
golden, approval record or runtime was changed. The only new file written is
this review report.

No native launch, build, heavy test, production-app capture, screen-reader or
keyboard/visual usability test was run or claimed for this prose-only review.
Implementation correctness, actual refusal of stale targets, race behavior,
permission/integrity observations, redaction and budget enforcement must still
be proved in each slice's executable evidence. The coordinating agent's final
P4.2 regression and acceptance work is separate and remains an entry prerequisite.

The scoped design is approved; runtime entry and all subsequent slice/phase
acceptance decisions remain independently gated and must use the actual
maintainer/delegation and reviewer identities.
