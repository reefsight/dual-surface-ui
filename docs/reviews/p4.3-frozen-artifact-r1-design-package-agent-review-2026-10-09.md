## Method and compatibility conclusions

- The new private ten-key freeze is one fixed R1 profile, not a selectable
  approval mechanism. Its three literal report paths and actual security,
  interoperability and package identities are explicit. Old D2 profile/report
  substitution remains a required negative; every old failure and consumed
  approval stays immutable. New Suite19 includes this reviewed design in both
  inventories; source identity still recursively binds accepted collector and
  foundation sources.
- Native initial admission precedes all candidate/owned workers, run-root
  creation and compilation; compilation is absent from that branch. Admission
  must also occur before each subsequent worker and lane. Implementers must not
  leave an SDK/worker invocation ahead of that initial admission while moving
  only the later native call. Missing/wrong prebuilt bytes fail closed rather
  than silently rebuild. This is a source-review/test requirement, not an
  observation that the current launcher already meets it.
- Four literal companion files plus separate suite/fixture DLL pins cover the
  reviewed application artifacts. The two fixed adjacent runtimeconfig.dev
  paths must be absent before workers/lanes. Neither directory discovery nor
  PDB/apphost execution is admitted. This boundary uses the existing admitted
  SDK/shared .NET/WPF toolchain; it is not hostile-host, ambient-runtime or
  privileged filesystem-tamper resistance.
- Explicit seven suite compile items plus six existing linked collector/
  foundation items remove unbound default application-source discovery. Both
  inventories and the provenance fourteen-file list must reflect the actual
  fixed source inputs. Unknown repository/ancestor MSBuild imports must stop
  qualification; the proposed provenance cannot make them safe by omitting them.
- The real source candidate commit precedes qualification. SourceLink and
  informational revision must genuinely refer to that commit, while subsequent
  documentation HEADs are not substituted as build provenance. No commit hash
  is embedded into the source set that forms that same commit; provenance,
  source-review reports, decision and freeze remain outside source/DLL hash
  inputs. The decision binds actual evidence/provenance/DLL, and freeze binds
  complete decision bytes, avoiding a source-to-freeze-to-binary hash cycle.
- C#/JS must agree on closed original-byte parsing, limits, ordered paths,
  identities and all semantic cross-bindings. Pinned claims are not proof that
  a fresh compile or genuine metadata observation occurred. Independent final
  qualification reviews must inspect retained actual terminals/source tree and
  observations, not merely accept a self-consistent JSON record.
- This is an internal build/admission remediation. Frozen core/native wire
  schemas, stable errors, reference/session authority, public exports,
  dependencies, npm allowlist, fixture/oracle and UIA guards remain unchanged.
  No public protocol version/ADR change, model eval or new runtime capability is
  justified by this design. Existing P4.3 scenario counts and resource limits
  remain mandatory; no narrower qualification substitutes for S2/S3/S4.
