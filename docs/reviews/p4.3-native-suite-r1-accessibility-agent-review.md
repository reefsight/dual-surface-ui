## Initial finding R1-SRC-INT-01

Severity: Low. Numeric scalar parser boundary is not enforced.

The accepted design caps provenance scalars at 512 UTF-8 bytes. Both new
parsers enforce that bound for strings and decoded keys but do not check the
length of numeric tokens. Own pure command `71def0` supplied 513 ASCII digits
to the Node raw parser: it accepted them and converted the value to a
nonfinite number. Static C# inspection shows that its token loop also has no
numeric-byte bound; no C# execution was performed by this reviewer.

The closed provenance schema has no valid numeric fields and rejects these
values during later typed admission. This finding does not establish an
authorization bypass or a successful malicious provenance record. It concerns
the promised raw-parser bound and incomplete boundary vectors.

Require both parsers to reject numeric tokens over 512 original UTF-8 bytes,
with matching 512/513 boundary vectors. Preserve the existing string/key,
depth, token and overall file bounds; do not weaken the closed typed grammar.
Actual revised source and pure proof must then be reviewed against new pins.
