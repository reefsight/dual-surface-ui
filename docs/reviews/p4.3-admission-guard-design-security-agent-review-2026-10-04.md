## Findings, refinements and security disposition

No new blocking security design finding remains in the final target.

The observer authority/first-latch precision point I sent during this review
is explicit in the final design: the production callback may perform only
closed enum-pair/context validation and a single immutable assignment. It may
not perform IO, logging, clock/deadline checks, provider/native operations,
including on invalid or already-latched input. This is a design requirement
to check in actual callsites, not an assertion about unseen implementation.

Root reported accessibility/interoperability's Medium ambiguity in the original
desktop name guard. I independently checked the final remedy against the
existing source's compound `desktop == 0 || ObjectName(...) != "Default"`.
The final `desktop-name-or-null` group preserves short-circuiting and does not
assert a measured name mismatch when no name was read. A refusal inside the
already-required ObjectName operand remains its own `name-query` group;
station `name-value` remains only its existing computed comparison. The
refinement is sound design, without a new probe, extra read or guard relaxation.
It was not my original discovery and is not a demonstrated OS defect.

My initial nonblocking scope note described process-restart construction as
coarse under the first proposal. The final design explicitly includes that
existing constructor within process-restart/startup/setup-admission, alongside
bootstrap startup and window-replacement setup. Source confirms Launch already
constructs admission at restart; this adds no new constructor, process lookup or
OS authority. The earlier coarse-only note is superseded, not a final limit.

## Design properties approved

- Constructor-only capability: the optional internal observer receives only
  two closed enum values, never a Process, handle, token/SID, native return value,
  error object, path, name, success trace, timestamp or duration. It is enabled
  only for this constructor and cleared in finally on success or refusal.
  Later Observe/context/peer checks and cleanup cannot reuse it. Standalone
  no-observer callers keep exactly the same coarse failure behavior.
- No authority return: an existing explicit Unavailable refusal notifies once
  and then throws the same CaptureException(Unavailable) unconditionally.
  Observer errors are withheld, not retried or substituted for the guard. Invalid
  enum/context input results only in unchanged coarse failure. It cannot permit
  admission, mutation, fallback, broader enumeration or continued SDK work.
- First-primary preservation: the enum pair is validated with its allowed host
  context before one immutable tuple assignment. Both optional fields are set
  together or neither is set; later notifications and cleanup cannot change
  them. A callback must not tag an SDK/managed exception or deadline merely
  because a check was last entered. Existing post-read/deadline and short-circuit
  precedence remain unchanged. Atomic tuple assignment is not an atomic OS/UIA
  ownership claim or an extension to the trusted serial caller model.
- Exact pair grammar: non-null check/guard values require a table-listed pair,
  guard-refused/Unavailable and setup-admission at exactly one of
  bootstrap/startup, process-restart/startup or window-replacement/setup. Every
  other primary has both explicit null values. Mixed nulls, invalid enum values,
  valid enums in invalid combinations, stale context, timeout, SDK fault,
  capture, later peer checks and cleanup cannot claim constructor detail.
- Accurate grouped meaning: subject, worker and current-subject token checks
  retain their distinct static scopes while sharing the eight closed token
  guard groups. Token capacity, result, scalar-size, SID-pointer/body and desktop
  groups describe existing branch groups, not individual native values or which
  operand of a compound condition failed. Name/query/integrity/session data stays
  private. Nested helper context must remain correctly attributed without a
  duplicate call or diagnostic reread.
- Closed negative-only channel: D2 has the distinct
  `p4.3-native-capture-suite-d2-failure` kind and exactly fourteen required flat
  keys, adding only admissionCheck/admissionGuard. Fourteen string/null slots
  plus the root use30 tokens;4096 bytes/depth2/token32/string128 need no increase.
  D1's exact twelve-key parser remains separate and must reject D2 shape/kind.
  Decoder/duplicate/key/type/cross-field/pin/timestamp safeguards remain; record
  time is production UTC publication time after required cleanup, not failure
  time or duration.
- Output containment: reuse only the already-admitted fixed failure filename,
  empty owned output capability, regular single-link/ancestor/final-path guards,
  once-only existing cleanup and CreateNew publication. No extra post-refusal
  provider/token/desktop query is added. The read-only CLI admits the fixed D2
  freeze before reading one bounded failure file and emits original-byte digest
  plus `nativeAccepted:false`; it cannot inspect partial content or supply
  successful case/pair facts. Success topology still rejects failure.json.
- New binding/entry, no inherited authority: the component becomes its original
  ten source paths plus this design, and suite becomes its original D1 seventeen
  plus this design. Changed admission bytes require a new independently
  reproduced component digest pinned in both suite binders, not staleaf7. No
  bound source file contains its own aggregate or mutable approvals. Old C0/D1/
  component/S1/foundation records remain historical and unchanged. D2 alone uses
  its new fixed three-role source reports, execution entry and freeze paths,
  existing strict canonical metadata, whole-report blobs and current binaries;
  no caller-selected review pins or D1 fallback can admit changed source.
- Scoped count change only if required: the permitted pure managed unit-summary

## Accepted limitations and non-claims

Additional labels may locate only a source guard group, not an OS cause or
individual native operand. They do not retrospectively diagnose D1 or C0,
authenticate the actual writer cryptographically, prove successful cleanup,
or make a failed attempt pass. No future tags or missing-label inference are
invented here. External kill, early output denial, blocked cleanup, stream
overflow or publication refusal may still leave no usable artifact.

The actual internal callback must be bounded trusted code; catch/withhold is
not hard containment of process termination or hostile blocking code. Existing
sequential native/provider/filesystem checks still do not prove unseen ABA,
hostile provider allocation bounds, per-getter hard latency or hostile local
administrator containment. The design introduces no broader concurrency claim.
Timestamp parsing proves format/calendar, not clock-origin provenance.

The original complete native22/32 first/repeat, independent positive artifact
reviews and separate S2 runtime decision remain mandatory. S3/S4, actual OS
negatives, P4.4 Rust qualification/comparison, authenticated host/macOS and full
P4.3/Phase4 exit are unchanged. A real session/desktop/security change or broader
authority requirement needs human direction; no guard bypass is approved.
