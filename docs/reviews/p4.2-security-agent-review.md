## Accepted lower risks and limitations

The local checkout, SDK cache and per-user temporary directories are trusted
inputs. The setup ready marker/version check does not authenticate every cached
SDK file on each later run. Native file checks reject leaf reparse points but
are not a defense against same-user concurrent path replacement, ancestor
junctions, or a malicious same-named fixture binary. The Node artifact reader
uses stat/read/recheck rather than the fixed-allocation review-record reader.
These are accepted Low risks for offline, synthetic, developer-owned tooling;
they are not acceptable guarantees for a privileged or remotely callable
production service.

The runner intentionally prints its local evidence-directory path. That console
line is not sanitized for publication; documentation/evidence assembly must
continue excluding it. The checked-in golden has no such path. Temporary state
records and failed runs are retained for diagnosis, not automatically deleted;
each run is bounded, but accumulation across many runs needs host-owned cleanup.

Frozen evidence is single-host Windows/DPI/locale coverage. Passing admission
and hashes prove consistency and source binding, not independent OS attestation,
absence of all possible secrets, successful deadline kills, or hostile-provider
resilience. Event evidence covers property names/order without value payloads;
it does not prove a general structure-event subscription or every event type.
The empty-value guard and closed schemas are stronger evidence here than a
sentinel text scan alone.
